# P30 · R32 产品推荐合规闸：pitch 不复述产品名就凑不到「同句」

## 2. 缺陷与层判定

**层：规则层（R32 实现 `_product_gate` + 共用的 `TIER_RE`）**

- 现象：`生成产品推荐` 带 pitch「按您目前的 L3 情况，每天一包」「您这期分级是 3 级，可以试试」「您缓解期保持得不错，配一包当加餐」「按您目前的三级管理情况，每天一包」全部 committed。
- 定位：`_product_gate` 只在**同一句里同时出现产品名**与分层 / 缓解字样时拦。sku 名由 `text_of` 另起一行追加，pitch 不复述「英纽林」就永远不同句（W53 0783 被拦正因为 pitch 自带「英纽林」）。另外 r68 的「三级管理」`TIER_RE` 认不出。
- 对照：同组判对的 0783（pitch 里自带产品名）被拦；r74 / r79（无分层字样）放行——差别只在 pitch 有没有复述产品名，不在语义。

## 3. 根因修

**P30a（proposal 48）**：IR R32 的「同句」指**推荐这件产品的那句话**与分层 / 缓解字样同句。`生成产品推荐` 的 pitch 就是这件 sku 的推荐话术，产品是它每一句的隐含主语，所以 pitch 的每一句都按「提及产品的句子」审；其它来源（`审核输出内容` 的正文等）仍按字面产品名判同句。另在 `TIER_RE` 上追加「N 级管理 / 管控」这一服务分层口语写法（不与「三级医院 / 2 级低血糖」混淆）。追加写在 `_product_gate` 之前的单独一行 `TIER_RE = re.compile(TIER_RE.pattern + …)`，不改原定义行，避免与 P35a 补丁重叠。

## 4. 朴素修（v5 (i) 乙-2：五条预登记机械规则逐条判）

| # | 机械规则 | 适用 | 理由 / 对应提案 |
|---|---|---|---|
| 1 | 放宽阈值 | 不适用 | R32 没有数值阈值；把「同句」窗口放宽到全文能救 r67 / r69 / r75，但 r68 的「三级管理」`TIER_RE` 根本认不出，窗口再宽也拒不了，Dᵢ 过不全 |
| 2 | 跳过缺参数的校验 | 不适用 | 这是**漏拦**（该拒没拒）缺陷；「缺参数就跳过」只会让规则更少触发，不可能把 commit 变成拒绝 |
| 3 | 删掉命中的规则分支 | 适用 | P30b1：删「尾注已附 → 放行」分支 |
| 4 | hard 改 soft | 不适用 | 漏拦缺陷；hard 改 soft 只会让拒绝变提示，Dᵢ 要求的 rejected 反而更不可能出现 |
| 5 | 把 Dᵢ 命中的字面量加进匹配 | 适用 | P30b2：Dᵢ 字面进 `PRODUCT_WORDS` / `TIER_RE` |

- **P30b1（proposal 49，规则 3 · 删掉命中的规则分支）**：Dᵢ 在 R32 里走的放行分支是「尾注已附（attached is True）→ 放行」；把这个判断删去，产品推荐一律被 R32 拒。
- **P30b2（proposal 50，规则 5 · 把 Dᵢ 命中的字面量加进匹配）**：把 Dᵢ pitch 里的「每天一包 / 可以试试 / 配一包」加进 `PRODUCT_WORDS`，把「三级管理」加进 `TIER_RE`，于是这几句在字面上「同句含产品」。
