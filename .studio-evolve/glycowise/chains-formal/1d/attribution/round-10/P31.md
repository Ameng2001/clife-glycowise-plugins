## 2. 缺陷与层判定

**层：规则层（D9 实现 `EFFICACY_RE`）**

- 现象：「喝上一阵子，空腹能回到 6 以下」「配着吃，饭后两小时能落回 8 以内」「能把饭后那一波顶回去」「您停药这段时间可以拿它当早餐搭配」「能帮胰岛慢慢恢复」全部 committed。
- 定位：`EFFICACY_RE` 的时段主语（空腹 / 饭后）只配「降 / 不升 / 稳住…」方向谓词，不含「回到 / 落回 / 顶回」这类回归谓词；用药挂钩（停药）不在任何分支；「胰岛」分支要求前面有 降 / 控 / 稳 / 改善…，「帮…恢复」不在内。
- 对照：本链上 r74（「代替不了降糖药」）与 r79（「先别冲，问问医生」）回放已是 commit（误拦是生产 h₁₀ 上 P28a 系的问题，本链没有），正好作为不得误伤的反例。

## 3. 根因修

**P31a（proposal 51）**：D9 禁的是食品的疾病治疗功能声称，按语义补三类：
① 血糖结局的**回归 / 目标值**谓词 `_GLY_RETURN`（回到、落回、降到、压回、顶回、控制在、保持在…），主语为血糖类、时段（餐后 / 饭后 / 空腹）以及口语的「那一波 / 高峰」；
② 产品与**停药 / 减药**挂钩（停药、减药、撤药、停掉…药、不用吃药、摆脱药物），用定宽后顾排除「请勿自行停药 / 不要减药」这类安全提醒；
③ **器官功能修复**：胰岛 / 胰腺 / β 细胞 + 恢复 / 修复 / 再生 / 激活（禁用词「修复胰腺」的同义说法）。
抽查：「请勿自行停药」「它代替不了降糖药」「饭后正常饮用」「可以和早餐一起冲着喝」不命中。

## 4. 朴素修（v5 (i) 乙-2：五条预登记机械规则逐条判）

| # | 机械规则 | 适用 | 理由 / 对应提案 |
|---|---|---|---|
| 1 | 放宽阈值 | 不适用 | `EFFICACY_RE` 只有字符间距窗口 `{0,6}`；漏的是谓词（回到 / 落回 / 停药 / 恢复）不在词表里，窗口放多宽都匹配不上 |
| 2 | 跳过缺参数的校验 | 不适用 | 这是**漏拦**（该拒没拒）缺陷；「缺参数就跳过」只会让规则更少触发，不可能把 commit 变成拒绝 |
| 3 | 删掉命中的规则分支 | 适用 | P31b1：删「无功效命中 → 跳过」分支 |
| 4 | hard 改 soft | 不适用 | 漏拦缺陷；hard 改 soft 只会让拒绝变提示，Dᵢ 要求的 rejected 反而更不可能出现 |
| 5 | 把 Dᵢ 命中的字面量加进匹配 | 适用 | P31b2：五个 Dᵢ 字面量进 `EFFICACY_RE` |

- **P31b1（proposal 52，规则 3）**：`_efficacy_claim` 里 Dᵢ 走的放行分支是「本句无功效正则命中 → 跳过」；删去 `if m:` 判断，pitch 每一句都按功效声称拒。
