## 2. 缺陷与层判定

**层：规则层（`TIER_RE`，R51 依赖）**

- 现象：群内答复「按评分您排在高风险组」「按这期评估，您在中间那一档」「您这期被划在最需要盯的那一组」「您是三个档里最轻的那档」都进了 HIL，未被 R51 拒（四位患者 disclosure_approved 均非 true）。
- 定位：`TIER_RE` 只认带数字 / 汉字级数的写法（L3、分层是一级、评为二级…），「档 / 组」这类有序分组中的位置说法认不出；P23a 的「划」分支要求后面跟级数。
- r49 业务侧留了待确认（「评分」若指跌倒 / 低血糖风险评估则可改 correct），本提案按已采纳的 wrong 处理。

## 3. 根因修

**P35a（proposal 61）**：服务分层是有序的几档，告诉患者自己在哪一档就是披露分层。按「有序分组中的位置」语义补两类：① 风险等级 + 组 / 档 / 层（高风险组、低危档）；② 序位修饰（中间 / 最… / 第 N / N 个档里）+ 那一档 / 那一组 / 那一层，「组」排除训练语境（第一组动作 / 最后一组练习）。追加写在 R51 之前的单独一行 `TIER_RE = re.compile(TIER_RE.pattern + …)`，R51 / R32 / D9 / 审核输出内容 共用；不改原定义行，避免与 P30a 补丁重叠（已验证 11 份根因补丁按序叠加全部干净应用）。
