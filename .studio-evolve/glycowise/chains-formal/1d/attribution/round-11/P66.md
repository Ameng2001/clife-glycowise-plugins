# P66 · 群内宣告缓解结论未拦（绕开「医师面诊告知，唯一」）

- 链：1d（本链当前状态 = h_s + P24a + P25a + P29a + P31a + P32a + P34a–P40a）
- 窗口：2026-W54
- 来源案例（Dᵢ，`P66-Di.yaml`）：结论层与分层-r60（t-0879）
- 缺陷层：规则层（R29 只审缓解判定的写入，没有挂到对患者的群消息上）
- 提案：P66a（根因修，proposal 123）；没有可用的朴素修

## 1. 复现

群里回周先生（P0007）：「您已经达到缓解标准了，恭喜」。期望 rejected(R29_缓解判定)，本链实际 群内答复患者·commit（进 HIL）。

周先生的情况：停药 105 天，HbA1c 6.1，按化验其实满足缓解标准，但医师还没有正式判定（缓解时钟 running，没有 RemissionAssessment）。另外他 disclosure_approved=true，所以 R51 不会响。

## 2. 根因

IR 里「判定缓解结果」的 HIL 写的是「医师（面诊告知，唯一）」：缓解结论只能由医师面诊告知患者，这是唯一渠道。在群里说「您已经达到缓解标准了」，既抢在医师判定之前，又绕开了面诊告知。患者按化验满不满足标准，都不能这样发。

现有 R29 只做两件事：审「判定缓解结果」写入的 status，以及「未达标却用缓解字样」。它没有挂在「群内答复患者」上，就算挂上，周先生达标，「未达标」那一支也不会响。现有规则里没有任何一条覆盖「缓解结论只能面诊告知」。业务侧的意见是「期望规则名请本体负责人定」，这里取 R29_缓解判定，与 case 的 expect 一致。

## 3. 根因修 P66a（proposal 123）

- `__init__.py`：在「群内答复患者」的 post_rules 里追加 `R29_缓解判定`。
- `_fde.py`：
  - 新增 `REMISSION_CONCLUSION_RE`，只收**宣告缓解结论**的说法：
    - 达到 / 达成 / 实现 / 进入 / 属于 / 算是 / 已经是 + 缓解 / 逆转；
    - 缓解 / 逆转 + 标准 / 状态 / 成功，但后面跟「还 / 尚 / 未 / 没」时不算；
    - 糖尿病 / 血糖 / 病情 + （已经）缓解了 / 逆转了。
  - 不收症状语境（「头晕缓解了吗」「症状有所缓解」），也不收路径介绍（「缓解路径还在评估」）。
  - R29 开头先看本次暂存的对外内容：如果是对患者的消息（target_audience 是患者群或患者），**只审**是否在宣告缓解结论，宣告了就拒（「缓解结论只能由医师面诊告知（唯一渠道），不得在群内 / 线上宣告」），否则放行。原来「未达标禁用缓解字样」那一支只对判定写入生效，不会套到群消息里「症状缓解」这类用法上。
  - 「判定缓解结果」这条路径没有对外暂存内容，行为不变。

补丁 `P66a.patch` 共 47 行，改了 `__init__.py` 和 `_fde.py`。
