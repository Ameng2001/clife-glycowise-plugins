## 2. 定位

`_fde.py` 的 `r44`：

1. 先删掉被否定的闭环提法（P17a：「先别结案」「暂不闭环」）得到 `act_eff`；
2. 显式闭环词（闭环 / 关闭 / 结案 / 解除 / resolved …）命中即判闭环；
3. 否则 `RISK_CLEARED_RE`（P22a：「脱离 / 排除 / 消除 … 风险」「风险已过去」「度过危险期」）命中也判闭环；
4. 判闭环且患者用磺脲 / 长效或预混胰岛素就拒。

第 3 步把「风险已结束」这种**措辞**直接当成**闭环处置**。IR 里 R44 的 check 是「拒绝写入 alert.resolved」；P22a 的注释也写明 IR 允许的是 value_recovered（值已回升 + 保持复发观察窗）。r37 / r39 的回执在同一句里明确保持告警打开（「先别结案」「明早再看一次」「继续观察 24 小时」），处置是 value_recovered，不是 resolved。第 3 步没看回执的处置，只看了措辞。

措辞不当（对磺脲患者说「脱离风险」）是真问题，但本动作 HIL 是 always（健管师 / 值班医师），业务侧要的是放行进人审改措辞。规则层整条拒反而让这次告警没有响应记录（C20 要求留响应）。

## 3. 根因修 P25a（proposal 34）

- 把 P17a 的否定式抽成 `NEG_CLOSE_RE`（行为不变），新增 `KEEP_OPEN_RE`：继续 / 保持 / 持续观察、观察 N 小时 / 天、明早 / 明天 / 今晚 … 再看 / 再测 / 复测 / 复查、再看一次、复发观察；
- 第 3 步改成：「风险已结束」措辞只是推断闭环的依据，回执里还有被否定的闭环提法或保留观察窗时，它记的是 value_recovered，不判闭环；
- 第 2 步不动：显式闭环词（没被否定）照拦，所以「确认脱离风险，继续观察后闭环」照样拒。

补丁：`P25a.patch`，34 行（+11 −3），只改 `_fde.py`。
