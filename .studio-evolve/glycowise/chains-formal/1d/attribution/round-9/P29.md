# P29 · D9 漏拦「波动形态」类功效声称（round 9 · 1d 链 · 2026-W52）

- 基线：1d 链当前状态 h_s = h_s + P24a + P25a（`chains-formal/1d/state/plugins/glycowise/`）
- 来源案例集 Dᵢ：`P29-Di.yaml` = { 产品与机构合规-r56 }（轨迹 t-20261025-0618）
- 缺陷层：规则层（`_fde.py` · `EFFICACY_RE` / `_efficacy_claim`，挂在 `D9_产品功效声称拦截`）
- 提案：P29a（proposal 46，根因修，进链）；P29b1（proposal 47，朴素修·规则 5，只进 P-A）

## 1 现象

口语「黄伯（P0045）推英纽林 sku-ynl-01，话术：每天一包，血糖曲线会变平；他儿子在外地。」路由成
`生成产品推荐{patient_id: P0045, sku_id: sku-ynl-01, pitch: 每天一包，血糖曲线会变平}`。
业务侧期望 `rejected(D9_产品功效声称拦截)`：把食品和「血糖曲线变平」挂钩是功效声称；P0045 有营销同意，C4 通过，问题只在话术。
本链状态回放：`action(生成产品推荐)·commit`，原题和两条变体都 fail。

## 2 根因

D9 的 IR 依据是食品安全法 71、73 条和广告法 17 条：食品不得声称疾病预防或治疗功能。P16a 补上了功效声称判定，P24a 按语义归纳出两类：
① 对血糖结局的方向性作用（降 / 不冲高 / 稳住…）；② 疗效与起效用语（见效 / 效果更好 / N 天看到）。

本例属于这两类都没覆盖的第三类：**对血糖波动形态的作用声称**。「曲线会变平」的意思是吃了以后血糖由起伏变平缓，是「稳定血糖」的另一种说法。
现有式子在血糖主语后只收「波动小 / 波动少」这类静态搭配，没有收「变平 / 拉平 / 平下来 / 削峰 / 波动变小」这类**变化谓词**，所以「血糖曲线会变平」一个子模式都没命中，D9 返回 ok。

已排除的其它可能：
- 产品识别：`product_mention` 能命中（推荐正文里有 SKU 名和「固体饮料」尾注词），而且 `_efficacy_claim` 在有 `pitch` 时逐句都查，不是识别漏了。
- R32：R32 管的是产品与分层 / 缓解同句（`_product_gate`），本句没有分层或缓解字样，R32 不响是对的。
- 路由：意图、参数与口语一致，pitch 原样转写，不是路由层的问题。

## 3 修法

### P29a（proposal 46）· 根因修
在 `EFFICACY_RE` 里按语义加入「平滑化」谓词类，覆盖由起伏变平缓的变化谓词：
- `_GLY_SMOOTH`：变平、拉平、抹平、压平、削平、摊平、平下来、平稳下来、平缓下来、变（得）平稳 / 平缓、变稳、稳下来、变缓、削峰、削掉。可接的主语有血糖类（血糖 / 糖化 / HbA1c / 胰岛）、时段（餐后 / 饭后 / 空腹），以及「曲线 / 波动 / 峰值 / 起伏」（控糖话术里单说「曲线」「峰值」就是指血糖曲线和餐后峰值）。
- `_GLY_SHRINK`：（会 / 就 / 能）变小 / 更少 / 减小 / 减少 / 减轻。只接「曲线 / 波动 / 峰值 / 起伏」这几个主语。接血糖或时段主语时范围太宽（比如「饭后喝的量减少」），所以不收。
- 和 P24a 一样不收静态状态词：「血糖平稳」「曲线平」「血糖已稳定」是在描述当前状态，不算声称。

补丁：`P29a.patch`，+12 / −0（其中 7 行注释、3 行谓词定义、2 行接入 `EFFICACY_RE`），只改 `_fde.py`。

### P29b1（proposal 47）· 朴素修（规则 5：把 Dᵢ 命中的字面量加进匹配）
在 `EFFICACY_RE` 末尾加一个字面量分支 `|血糖曲线会变平`。
补丁：`P29b1.patch`，+2 / −1（把原来的最后一行拆成两行再加注释），只改 `_fde.py`。

## 4 五条朴素规则 × 本缺陷

本缺陷的性质是漏拦：该拒的被 commit 了。要让 Dᵢ 通过，D9 必须多拒这一条。规则 1–4 都只能让本体变松（拒得更少），所以机械套用后 Dᵢ 不可能通过。

| # | 机械规则 | 适用？ | 理由 |
|---|---|---|---|
| 1 | 放宽阈值 | 不适用 | D9 没有数值阈值可调。式子里唯一的「阈值」是主语与谓词之间的字距窗口 `{0,6}`，但本句里根本没有一个已登记的谓词，窗口放多宽都匹配不到；放宽本身也是把规则变松，方向反了。 |
| 2 | 跳过缺参数的校验 | 不适用 | 意图参数齐全（patient_id / sku_id / pitch 都在），没有因缺参数被跳过或误拒的校验；跳过校验只会更放行，不能让 D9 拒。 |
| 3 | 删掉命中的规则分支 | 不适用 | Dᵢ 没有命中任何拒绝分支（D9 返回 ok，违规列表为空），没有分支可删；删分支只会减少拒绝。把「功效正则必须命中」这个条件删掉，让任何带 pitch 的推荐都拒，不是删一个「命中的分支」，而是重写规则，超出了机械套用的范围，所以不立案。 |
| 4 | hard 改 soft | 不适用 | D9 已经是 hard，本例的问题是它没响，不是响了却拦得太硬。把 hard 改成 soft 只会让本来能拦的也不拦。 |
| 5 | 把 Dᵢ 命中的字面量加进匹配 | **适用 → P29b1** | 把 Dᵢ 的话术字面量「血糖曲线会变平」加成 `EFFICACY_RE` 的一个分支，Dᵢ 原题和两条变体都会被 D9 拒（实测 3/3 通过）。 |

## 6 误伤面（只用案例文件估计，没看任何裁决）

- 全案例库（`cases/real` + `cases/sim`，共 614 条，1519 行含变体）在 h_s、P29a、P29b1 三个状态上各回放一次，逐行比对 pass 和 actual：**两份提案都只有 产品与机构合规-r56 的 3 行变了（0→1）**，其它 611 条结果不变（h_s 原题 529/614，两个沙箱都是 530/614）。
- 新增的 SETUP_DIVERGED：134 行 / 54 条案例。全部来自同一个前序步骤 t-20261025-0618（`生成产品推荐`，pitch「每天一包，血糖曲线会变平」）。这 54 条都是 W52 窗口里排在 0618 之后的案例，候选本体把这一步历史改写成了拒绝，这是反事实，按约定照常评判。这 54 条的判定一条都没变。两份提案在这一项上完全相同。
- 案例库里出现的 26 种不同 pitch 全部过了一遍：P29a 相对 h_s 只多命中「每天一包，血糖曲线会变平」这一种。中性话术（「作为日常饮食的补充」「可以和早餐一起冲着喝」「是固体饮料，按说明每天冲一包」「刘阿姨血糖已稳定…」等）一条都没新增命中。
- 插件源码里的所有字符串常量（种子模板、方案草稿、告警模板）在 P29a 下没有新增命中。
- 两份提案的差别不在案例库上，而在泛化。正则层面的探针（不是 runner）：「吃了以后餐后曲线平下来」「餐后峰值能削掉一截」「波动会变小」「起伏变小了」「把餐后血糖拉平」，P29a 都命中，P29b1 一条都不命中。反过来，「血糖一直平稳」「曲线平」「心情平稳下来」「空腹喝的量减少」「血糖仪试纸用量减少」，两份都不命中。
- 风险：P29a 的「曲线 / 峰值 + 平滑谓词」在带 pitch 的推荐里，凡是含这类说法的句子都会拒。如果有人在推荐正文里写「AGP 曲线变平稳了，可以考虑…」这种复述病情的话，也会被拦。按 D9 的法条口径，这本来就该改写，但可能会有少量需要人工改写的情况。
