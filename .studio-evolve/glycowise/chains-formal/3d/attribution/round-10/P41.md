# P41 · R32 产品推荐与分层 / 缓解同句：推荐话术不复述产品名就永不同句

- 链：3d · round 10 · 窗口 2026-W53 · 本体状态 h₁₀（= 生产，`chains-formal/3d/state/plugins/glycowise`）
- 层：规则层（R32 / D9 共用的 `_product_gate`）
- Dᵢ：`P41-Di.yaml` = 产品与机构合规-r67 / r68 / r69 / r75（t-20261025-0717 / 0718 / 0719 / 0781）
- 提案：P41a（proposal 75，根因修）· P41b1（proposal 76，朴素修 N5）

IR §4 R32：「产品推荐不得与服务分层结论、"缓解/逆转"字样同句出现」。四条话术都把推荐和分层 / 缓解写在同一句里，h₁₀ 全部放行。

## 2 定位

`_fde._product_gate` 逐句检查「句中有产品名 **且** 有分层 / 缓解字样」。产品名的来源是 `text_of`：pitch 原文、`ProductSku.name`（「英纽林」）、暂存的 OutboundContent 正文。`act_reco` 把正文拼成 `pitch + "\n固体饮料，不替代药物。\n" + 免责`，sku 名在 `text_of` 里也是单独一行。于是只要 pitch 本身不写「英纽林」，任何一句都不含产品名，闸永远不生效。

对照同组判对的 0783「文案提一下他已经进入缓解观察」：被 R32 / D9 拦，是因为路由写出的 pitch 自带「英纽林」。业务侧的判定标准两条一致，差别只在 pitch 有没有复述产品名——这不是业务差别，是实现把「推荐句」误当成「含产品名的句子」。

r68 另有一处：「三级管理」是服务分层 L3 的口语写法，`TIER_RE` 不认。

## 3 根因修 P41a（proposal 75）

按 IR 语义，「产品推荐句」就是推荐话术本身：`生成产品推荐` 的 pitch 每一句都是推荐句，不管有没有复述产品名。

- `_product_gate`：pitch 的句子（按同一个 `SENT_SPLIT` 切）直接算产品推荐句，再看是否同句含分层 / 缓解字样。
- `TIER_RE`：补「[一二三四1-4] 级管理」——服务分层 L1–L3 的同义写法（与已收的「分层是 N 级」「L3」同一概念），不是 Dᵢ 的句子字面量。

补丁 `P41a.patch`：`_fde.py` +6 / −1。

R32 和 D9 共用 `_product_gate`，IR 里 D9 的 check 表达式也是「同句含分层 / 缓解」，所以 D9 一起收紧，符合 IR。

## 4 朴素修：五条机械规则逐条判断

| # | 机械规则 | 适用？ | 理由 |
|---|---|---|---|
| N1 | 放宽阈值 | 不适用 | 闸里没有数值阈值；「放宽」只会让规则更难触发，而 Dᵢ 要的是拒绝 |
| N2 | 跳过缺参数的校验 | 不适用 | Dᵢ 错判不是参数缺失造成的；跳过校验只会更放行 |
| N3 | 删掉命中的规则分支 | 不适用 | Dᵢ 走的是循环条件为假的隐式放行路径，没有可删的显式放行分支。若删掉同句条件里的「句中有产品名」，r68 的「三级管理」`TIER_RE` 仍认不出，Dᵢ 不全过 |
| N4 | hard 改 soft | 不适用 | R32 本来就是 hard；改 soft 只会更放行 |
| N5 | 把 Dᵢ 命中的字面量加进匹配 | **适用 → P41b1** | 把 Dᵢ 话术里的「每天一包 / 可以试试 / 配一包」加进 `PRODUCT_WORDS`，把「三级管理」加进 `TIER_RE`，四条都同句命中 |

### P41b1（proposal 76，N5）

`PRODUCT_WORDS += ("每天一包", "可以试试", "配一包")`，`TIER_RE` 加字面量「三级管理」。补丁 `P41b1.patch`：`_fde.py` +2 / −1。
