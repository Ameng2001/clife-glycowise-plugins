## 2 定位

`_efficacy_claim` 由历轮补丁叠成：`EFFICACY_RE`（降 / 控 / 稳 + 指标）、`GLYCEMIC_OUTCOME_RE`（P27a，血糖走向谓词）、`EFFECT_CLAIM_RE`、`ONSET_CLAIM_RE`，以及 P28a 的反向判定（分句里出现血糖类指标即算暗示，`GLYCEMIC_INDICATOR_RE` = 血糖 / 糖化 / HbA1c / TIR / 葡萄糖 / 曲线 / 波动）。

漏网的原因是声称**对象**不在任何一张表里：

- 「空腹」「饭后」在控糖语境里指的就是那个时点的血糖（r70–r72），但只在 `GLYCEMIC_OUTCOME_RE` 里、而且谓词只有「不冲 / 平稳 / 降下来」，没有「回到 / 落回 / 顶回 / 那一波」；
- 「胰岛」只在 `EFFICACY_RE` 里，前面还要有「降 / 控 / 改善 / 治」，「帮……恢复」不算（r78）；而禁用词库里的「修复胰腺」就是同一种声称；
- 「停药」完全没在 D9 里（r76）。`生成产品推荐` 也没挂 D8。

对照同组判对的：0727「冲之前和冲完两小时各测一次血糖」、0792「喝的时候留意血糖有没有变化」都放行，是 P28a 的监测豁免在起作用。0618（W52）「血糖曲线会变平」被拦，是 P28a 的指标反向判定在起作用。漏的正是指标表之外的同义对象。

## 3 根因修 P42a（proposal 77）

把 D9 的声称对象补全为三类，与已有的四种判定放在同一个入口（产品话术句）：

1. **餐时血糖状态**：「空腹 / 餐后 / 饭后 / 餐前 / 睡前 / 晨起（+ N 小时）」后接结果谓词（回到 / 落回 / 降到 / 顶回 / 压住 / 稳在 / 冲到 / 不容易 / 那一波 / 高峰 / 平稳……）。只认「餐时词 + 结果谓词」，「饭后半小时冲一包」「饭后再冲」这类食用时间说明不算。
2. **胰岛 / 胰腺功能**：胰岛 / 胰腺 / β 细胞 + 恢复 / 修复 / 再生 / 改善，或「帮 / 养 / 护 / 修复 + 胰岛」。
3. **用药减停挂钩**：停药 / 减药 / 撤药 / 不用吃药 / 药量 / 停掉…药。先剔掉「别 / 不要 / 切勿（自行）停药」这类安全提醒再判。

补丁 `P42a.patch`：`_fde.py` +15 / −1。

## 4 朴素修：五条机械规则逐条判断

| # | 机械规则 | 适用？ | 理由 |
|---|---|---|---|
| N1 | 放宽阈值 | 不适用 | 正则里的字距窗口 {0,6} / {0,8} 算阈值，但放宽它解决不了「指标词不在表里」；放宽方向本身也只会更放行 |
| N2 | 跳过缺参数的校验 | 不适用 | 与参数缺失无关 |
| N3 | 删掉命中的规则分支 | 不适用 | Dᵢ 走的是「所有正则都不中 → 返回 None」的隐式放行，没有可删的显式放行分支（`if not prods` 没走到）。删掉匹配条件就成了「pitch 一律算声称」，那是把规则反过来，不是删分支 |
| N4 | hard 改 soft | 不适用 | 只会更放行 |
| N5 | 把 Dᵢ 命中的字面量加进匹配 | **适用 → P42b1** | 把 Dᵢ 里的「空腹 / 饭后 / 胰岛 / 停药」加进 `GLYCEMIC_INDICATOR_RE`，P28a 的反向判定就会拦下五条 |

### P42b1（proposal 78，N5）
