# P49 · R24b：G=16.8 时群内建议快走，没人拦

- 链：3d · round 10 · 窗口 2026-W53 · 本体状态 h₁₀
- 层：规则层（规则挂载 + R24b 的「运动前」判定）
- Dᵢ：`P49-Di.yaml` = 高血糖与波动-r52（t-20261025-0733）
- 提案：P49a（proposal 93，根因修）；五条朴素规则都不适用

## 1 缺陷

「王叔（P0031）现在 16.8，群里跟他说下楼快走半小时降一降」→ 路由 `群内答复患者`，message「王叔，您现在血糖 16.8，建议下楼快走半小时帮助降糖。」h₁₀ 进人审。IR R24b：G>16.7 无论酮体阴阳性一律不宜运动。王叔又是磺脲 + IAH 高危。期望 rejected(R24b)。

## 2 定位

- R24b 只挂在 `推送告警` 上（IR 另挂在 `记录餐食与运动事件`），`群内答复患者` 的 post_rules 没有它。
- `r24b` 只在 3 小时内有运动打卡（ContextEvent）时才评，G 取最近读数。王叔 seed 的最近读数是 10-24 23:45 的 6.4，也没有运动打卡；口语里的 16.8 是医生口述的当前值。

R24b 的意思是：运动前那一刻 G>16.7 就不该运动。给出运动建议的那一刻就是「运动前」，与患者打卡运动是同一处境。

## 3 根因修 P49a（proposal 93）

- `群内答复患者` 的 post_rules 补挂 R24b；
- `r24b`：对外内容里有运动建议（快走 / 散步 / 运动 / 跑步……，先剔掉「别 / 不宜 / 暂停 + 运动」这类否定建议）时也评；G 取内容里明说的当前值（「现在 / 当前 / 刚测 … X」，建议正是基于它给的），没说就取最近读数。原有的「近 3 小时运动打卡 + 最近读数」分支保留。

补丁 `P49a.patch`：`__init__.py` +1 / −0，`_fde.py` +15 / −2，合计 +16 / −2。
