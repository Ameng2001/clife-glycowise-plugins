## 2. 缺陷定位：规则层

IR 中 D12 的条件是「按 PlanDraft 内容分类与签发人 Credential 类型做匹配校验」。实现先读草稿，草稿不存在时 `content=""`，类别兜成「综合」；签发人是执业医师时 `scope=None`，直接放行。归属分流的前提是有内容可以分类，草稿不存在时这个判定无从做起，实现却把「无从判定」当成了「通过」。D12 是 签发方案 上唯一读草稿内容的 guard，D11a / C21 只看签发人和留痕。这与 P47a 处理 C20「指名对象不存在即拒」属于同一类缺口。同窗 0804「d-P0045-01 让陈营养师签」草稿存在，D12 判对了。

## 3. 提案

### P56a（根因修，proposal 108）

`d12` 在医师免检之前先判：`draft_id` 指名的 PlanDraft 不存在 → 拒，理由写明「不是现存的方案草稿，无法按内容判定签发归属」。如果这个编号是已签发方案（PlanSigned），另外提示「系统没有复签动作」。补丁：`P56a.patch`（16 行，+7 −0）。

### 朴素修：五条机械规则逐条判断

| 规则 | 适用 | 理由 |
|---|---|---|
| 1 放宽阈值 | 不适用 | D12 没有阈值。 |
| 2 跳过缺参数的校验 | 不适用 | 这是漏拦，方向相反。缺草稿内容时现在走的「兜成综合」已经等于跳过了校验，再跳也不会产生拒绝。 |
| 3 删掉命中的规则分支 | 不适用 | Dᵢ 命中的放行分支是 `if scope is None: return ok`（医师免检）。机械地删掉它，下一行 `cat not in scope` 会对 None 做成员判断并抛出 TypeError，runner 记为 ENGINE_ERROR（pass=null），不会变成 rejected(D12)，Dᵢ 不过。把「医师: None」从 `_SIGN_SCOPE` 表里删掉能让 Dᵢ 过，但那是改数据表，不是删分支，后果是所有医师签发一律被拒，所以不算本条的机械套用。 |
| 4 hard 改 soft | 不适用 | 方向相反。 |
| 5 把 Dᵢ 命中的字面量加进匹配 | **适用 → P56b1** | 把三个草稿号写成拒绝名单。 |

### P56b1（朴素修·规则 5，proposal 109）

`d12` 开头加：`draft_id ∈ {d-P0088-01, plan-P0066-w41, d-P0007-02}` → 拒。补丁：`P56b1.patch`（11 行，+2 −0）。
