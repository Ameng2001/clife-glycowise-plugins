## 2. 定位

`r44` 判「是否闭环」分两步：先剔除否定式（「先别结案」被剔掉），再看显式闭环词；都没有时，用 `RISK_CLEARED_RE` 认「风险已结束」式断言。r37 的「已经脱离风险」、r39 的「风险排除」命中这条正则，于是被当成闭环；两名患者都在用磺脲类药（P0045 磺脲、P0031 格列美脲），`hypo_risk` 为真，因此拒绝。

IR 的语义（ontology-map §R44 check）：「任一命中则**拒绝写入 alert.resolved**」。AlertEvent 状态机里 `value_recovered`（值已回升）和 `resolved`（已结束）是两个状态。R44 要挡的是「把告警判为已结束」，「值已回升 + 保持复发观察窗」是允许的。这两条回执都写明了还要继续观察（「先别结案，明早再看一次」「继续观察 24 小时」），所以去向是 value_recovered，不是 resolved。「脱离风险」只是措辞不当，按业务侧标注，应进人工审核，由审核人改成「值已回升」，不该把整条回执拒掉（C20 要求留下响应记录）。

对照同组判对的案例：低血糖安全-r08 / r13 / r27、因果链溯源-r14 / r15，写的都是「复测 x，继续观察 / 先不闭环」，没有断言词，所以放行。P22a 加 `RISK_CLEARED_RE` 时只按断言词判，没考虑同一条回执里明确保留观察窗的情况。

## 3. 提案

### P26a · 根因修（proposal 38）

只有在同一条回执**没有**保留复发观察窗时，「风险已结束」断言才算闭环。新增 `KEEP_OBSERVING_RE`（继续 / 保持 / 再 / 留 + 观察；观察窗 / 观察期；明早 / 明天 / N 小时 + 再看 / 复测；先别 / 暂不 + 结案 / 闭环），在 `RISK_CLEARED_RE` 命中后检查回执原文（检查原文，是因为否定式已经从 act_eff 里剔掉了）：匹配到就判为 value_recovered，不算闭环。显式闭环词（闭环、结案、关闭等，未被否定）照旧算闭环，不看有没有观察条款。

- 补丁：`P26a.patch`（28 行，+10 / −2，只改 `_fde.py`）
- `patch -p1 --dry-run -d chains-formal/ancestor-s`：通过；`py_compile`：通过
- Dᵢ（`--state h_prime --as-of 2026-10-25`）：2/2 原题，6/6 行全部通过（都是 commit）
