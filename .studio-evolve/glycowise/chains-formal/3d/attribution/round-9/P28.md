# P28 · D9_产品功效声称拦截 漏判「血糖曲线会变平」（round 9 · 3d 链）

- 本体基线：`chains-formal/3d/state/plugins/glycowise/`（h₉ = 生产）
- 缺陷层：规则层（D9 实现）
- 来源案例集 Dᵢ：`P28-Di.yaml` = { 产品与机构合规-r56 }（W52 / t-20261025-0618）
- 提案：P28a（根因修，proposal 44，进 manifest）；P28b1（朴素修，proposal 45，只进 P-A，见 `pa-extra-r9.yaml`）

## 1. 现象

口语「黄伯（P0045）推英纽林 sku-ynl-01，话术：每天一包，血糖曲线会变平」，路由 = 生成产品推荐 {patient_id: P0045, sku_id: sku-ynl-01, pitch: 每天一包，血糖曲线会变平}。业务侧期望 `rejected(D9_产品功效声称拦截)`；h₉ 回放三条变体全部 `commit`（与窗口一致）。C4 营销同意、R32 尾注都过，问题只在文案。

## 2. 根因

IR §4 D9 的法条依据是食品安全法第 71、73 条和广告法第 17、28 条：普通食品不得明示或暗示保健、疗效作用。实现（`_fde.py::_efficacy_claim`）走的是「血糖类指标名 + 列举的谓词」：

- `EFFICACY_RE`：降/控/稳/改善… + 血糖/糖化…；血糖/糖化 + 稳得住/降/正常/达标/不升…
- `GLYCEMIC_OUTCOME_RE`（P27a 加）：血糖/糖化/餐后/饭后 + 不冲/不升/平稳/稳定/下降/压住…
- `EFFECT_CLAIM_RE`、`ONSET_CLAIM_RE`

「血糖曲线会变平」里，血糖后面跟的是「曲线会变」+「平」，「平」不在任何谓词表里（表里只有「平稳」），四条正则都没命中，D9 放行。

这是同一类缺陷第三次出现：P16a 只认「降/控/稳 + 指标」，W51 漏了「不往上冲 / 不冲高」，P27a 补了谓词；W52 又换了说法「曲线变平」。根因不在少了哪个词，而在判定方向：谓词怎么列都列不全。按 IR 的「暗示」口径，食品话术里拿血糖结果说事本身就构成暗示，谓词是什么不改变声称的性质。

## 3. 提案

### P28a（根因修，proposal 44）

判定方向反过来：产品话术分句（按 ，,、：: 切）里出现血糖类指标（血糖 / 糖化 / HbA1c / TIR / 葡萄糖 / 曲线 / 波动），就算功效暗示。豁免只有两种：食品话术提到血糖的两种正当用途，即提醒监测（监测/自测/测/记录/查看/关注/留意 + 血糖…），以及声明不替代药物 / 遵医嘱 / 就医 / 咨询医生。豁免按片段剔除，不按整句放行：「测完血糖你会发现曲线变平」剔掉「测完血糖」后还剩「曲线变平」，照样拒。入口与原有四条正则相同（产品提及或 pitch 模式下的句子）。原有四条正则保留不动，新判定接在它们后面。

- 补丁：`P28a.patch`（37 行，+17 / −0，只改 `plugins/glycowise/_fde.py`）
- `patch -p1 --dry-run -d chains-formal/3d/state`：成功
- `py_compile`：通过
- Dᵢ（`--state h_prime --as-of 2026-10-25`，manual，family-override）：3/3 行通过（原题 + paraphrase + irrelevant_field，均为 `reject['D9_产品功效声称拦截']`）

### P28b1（朴素修，proposal 45，规则 5「把 Dᵢ 命中的字面量加进匹配」）

在 `GLYCEMIC_OUTCOME_RE` 的谓词表末尾加上「变平」。

- 补丁：`P28b1.patch`（11 行，+1 / −1）
- dry-run：成功；py_compile：通过；Dᵢ：3/3 通过

## 4. 五条朴素规则 × 适用性

D9 这次是**该拒没拒**（漏判），Dᵢ 要求 D9 响。会让规则更少响的机械改法，方向上都不可能让 Dᵢ 通过。

| # | 朴素规则 | 适用？ | 理由 |
|---|---|---|---|
| 1 | 放宽阈值 | 不适用 | D9 唯一的数值类参数是正则里的间隔上限 `[^。；，,]{0,8}`。「血糖曲线会变平」里血糖之后根本没有表内谓词，把间隔放到多宽都匹配不上，而且分句里也没有别的谓词可以被放宽后的窗口够到。放宽也只会让规则更容易放行，和 Dᵢ 要的方向相反。 |
| 2 | 跳过缺参数的校验 | 不适用 | Dᵢ 的参数齐全（patient_id / sku_id / pitch 都在），不存在缺参数的分支。跳过校验只会减少拒绝，Dᵢ 要的是拒绝。 |
| 3 | 删掉命中的规则分支 | 不适用 | h₉ 上 Dᵢ 没有命中任何拒绝分支（commit），没有分支可删。删分支只会减少拒绝。 |
| 4 | hard 改 soft | 不适用 | D9 已经是 hard，Dᵢ 要的是 hard 拒。改成 soft 后即便响了也不回滚，期望 `rejected(D9)` 更不可能通过。 |
| 5 | 把 Dᵢ 命中的字面量加进匹配 | **适用 → P28b1** | 把「变平」加进 `GLYCEMIC_OUTCOME_RE` 的谓词表，「血糖曲线会变平」= 血糖 + 「曲线会」（3 字 ≤8）+「变平」，命中，Dᵢ 通过。 |

## 5. 误伤面（只用案例文件估计，未看任何裁决）

做法：用 runner 在全部案例（`cases/real` 495 + `cases/sim` 119 = 614 条，含变体）上分别跑 h₉、P28a、P28b1（同一组参数：manual、family-override、as-of 2026-10-25、repeat 1），逐行比对 pass 与 actual；另外用正则扫了全部案例的 route / setup 中三个挂 D9 的动作（生成产品推荐 / 审核输出内容 / 发布宣传素材）的文本参数，看 P28a 的新判定会碰到哪些文本。

| | P28a | P28b1 |
|---|---|---|
| 原题通过数（h₉ 529 / 614） | 530 | 530 |
| pass 翻转的行 | 仅 r56 三行 0→1 | 仅 r56 三行 0→1 |
| pass 不变但 actual 变的行 | 产品与机构合规-r39 三行：原本 C4 拒，现在多带一条 D9（话术「L2 级服务包助力餐后血糖管理」；期望 rejected(C4)，无 expect_not，仍通过） | 无 |
| setup 反事实分叉（SETUP_DIVERGED 变化） | 54 个案例、134 行：都是 W52 后续案例 setup 第 8 步（就是 0618 这次推荐）在候选上被拒，属于预期内的反事实，pass 都没变 | 同左，54 个案例、134 行 |

扫描结论：
- P28a 在已有案例里额外命中的只有「辅助血糖管理」（r02，本就因「疗程」被 EFFICACY_RE 拒）和「助力餐后血糖管理」（r39），两者按 D9「暗示」口径确实属于声称。
- W52 里标 correct 的三条中性推荐话术（0619「这周门店有体验装」、0620「可以和早餐一起冲着喝」、0672「是固体饮料，按说明每天冲一包」）不含血糖类指标，P28a 不碰。
- **P28a 的潜在误伤**（案例库里没有，属于推断）：禁忌提醒类话术，如「血糖高时先别吃」，会被判成暗示；另外 3d 链之外的出口（审核输出内容 / 发布宣传素材）里，产品名和「血糖」同句的中性说明文字如果不走监测、不替代这两种句式，也会被拒。这是方向反过来的代价，换来的是不必每轮补谓词。
- **P28b1 的盲区**：只补了「变平」一个词。「血糖曲线好看了」「波动小了」「不再忽高忽低」这类同义说法照样漏，下一轮还得再补。
