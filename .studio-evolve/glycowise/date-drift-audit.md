# 日期漂移复核（2026-10-25）

## 1. 问题

部署域插件 `plugins/glycowise/_fde.py` 在导入时执行 `TODAY = date.today()`，另有多处 `datetime.now()`（「过去 24 小时」等）；种子数据也按「今天往前推 N 天」生成。真实与仿真案例里却可能写着绝对日期（「10 月 21 日凌晨」）或相对说法（「昨夜」）。于是**同一本体状态、同一批案例，在不同日期运行会得到不同结果**。由 round 7 演练 3d 链归因者首先报告（`chains-r7/3d/attribution/round-7.md` §5）。

## 2. 工具修正（astra，不改生产插件）

- `runner_onto_engine.py run --as-of YYYY-MM-DD[THH:MM]`：在引擎与插件导入之前替换标准库的 `date` / `datetime`，`date.today()` 固定为该日，`datetime.now()` 从该日 12:00（或给定时刻）起算、按进程内真实流逝前进（同一次运行里时间戳仍递增，写入键不撞车）。缺省仍用真实时钟。
- 每行结果记 `as_of`（运行时刻）；`growth_metrics` 读数记 `as_of`（去重列表）。
- `gate_decide`：基线与候选读数的运行日期不同 → 内 / 外关卡增量记 `AS_OF_MISMATCH:<基线>→<候选>`；旧读数无记录 → `AS_OF_UNKNOWN`。**只记标记、不改判定**（判据冻结）。
- `chain_drive run --as-of` 透传给 runner，链产物记 `as_of`。
- 验证：1d 链末态在仿真集上，`--as-of 2026-10-24` 复现 10-24 的结果（因果链溯源-01 判错），`--as-of 2026-10-25` 复现 10-25 的结果；跨天读数对 gate_decide 打出 `AS_OF_MISMATCH`，同日不打。

## 3. 哪些案例会随日期翻转

固定时钟扫描（全部 real 376 + sim 119 = 495 条，含变体）：

| 扫描 | 状态 | 时钟 | 翻转 |
|---|---|---|---|
| 跨日期 | 祖先 h₀ / P8 后 / P14 后 / P9a 后 / h₇ | 2026-10-23、24、25 各 12:00 | **只有 因果链溯源-01（sim，及其 2 个变体）**：10-23 ✓、10-24 ✗、10-25 ✓，五个状态完全一致 |
| 跨时刻 | h₇ | 2026-10-25 的 01:00 / 06:00 / 12:00 / 18:00 / 23:30 | 0 |
| 外延（仿真集） | h₇ | 10-22、10-24 12:00 / 23:50、10-25 00:10、10-26 | 因果链溯源-01（10-24、10-26 ✗）、**golden-02**（10-22 ✗，「昨夜」） |

所有历史运行都发生在 2026-10-23 至 10-25。这三天里 **real 案例没有一条翻转**；仿真集只有 因果链溯源-01 一条，且只在 10-24 判错，对所有状态的影响相同（只有基线与候选跨天时才会造出假差）。

## 4. 历史裁决复核

现存裁决 28 组（224 个臂裁决文件）。按命名约定还原每组的 Dᵢ 与留出集：只有 round 1（P2、P3、P4）的外关卡用 `sets/B-sim.yaml`（含 因果链溯源-01）；其余各组的 Dᵢ 与 B 全是 real 案例或不含该案例的 sim 案例。round 1 的三组裁决与 12 份读数（Dᵢ 与 B 的基线、候选）全部产生于 2026-10-23（git 首次提交 18:48，B 读数当晚 23:48 更新，同日），基线与候选同一天，该案例两侧都判对。

**结论：没有一个历史裁决受日期漂移影响，无需改判。**

## 6. 之后的约定

- formal 起，每一轮的全部 runner / chain_drive 调用都带 `--as-of <本轮开始日>`（如 `2026-10-26`），同一轮所有读数同一口径，跨天重跑可复现。
- gate_decide 出现 `AS_OF_MISMATCH` 的裁决须同日重算后再记台账。
- 插件里用绝对日期的案例（因果链溯源-01）与用「昨夜」的案例（golden-02）在报告中注明日期敏感；不改案例。
