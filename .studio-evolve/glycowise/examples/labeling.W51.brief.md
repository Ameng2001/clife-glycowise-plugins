## 每条怎么填

每条已给出 `utterance`（口语原句）和 `engine_actual`（引擎真实裁决）。本窗口没有 `cq_expect`，`suggested` 全空。

| 字段 | 填什么 |
|---|---|
| `label` | `correct` / `partial` / `wrong` 三选一 |
| `truth` | 一句话：业务上应有的结果，或引擎错在哪里。写业务事实 |
| `truth_expect` | 只有 `wrong` 必填，三选一：`query`、`action(动作名)`、`rejected(规则名)`。其余填 `null` |
| `layer` | 只有 `wrong` 填：`rule`（规则或动作实现错）、`router`（大模型路由错：选错动作、参数填错）、`seed`（演示数据缺字段）。拿不准写 `router` 并在 `note` 说明 |
| `reviewer` | 自己的 id 和角色，如 `{id: xxx, role: 医师}` |

- **correct**：引擎裁决就是业务应有的裁决。该起草后等人确认的进了人审（pending_hil），且动作选对、参数对；该拦的被对的规则拦了。
- **wrong**：方向错。该拦没拦、不该拦被拦、拦错规则、动作选错、参数对不上口语。
- **partial**：方向对、细节有瑕疵但不改变裁决，例如口语里的无关信息漏进了记录字段。partial 不落案例，**拿不准时倾向 wrong** 并在 truth 写清。

可选字段 `note`：对后续归因有用的观察，尽量写。
