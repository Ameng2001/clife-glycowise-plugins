我们在评测一个控糖服务本体的自进化闸门。四个真实窗口的口语已经经真实大模型路由进引擎执行，审计轨迹导出完毕。现在需要业务侧逐条判定：**引擎的裁决对不对**。标好的轨迹会落成真实案例，成为后续所有实验的留出集；标注质量直接决定实验结论能不能成立，所以请按业务真值标，不要按「机器建议」抄。

## 每条怎么填

每条已经给出：`utterance`（口语原句）、`engine_actual`（引擎真实裁决：查到几行 / committed 哪个动作 / pending_hil / rejected 被哪条规则拒）、`cq_expect`（口语小组写的参考类别，可能是错的）、`suggested`（机器比对结果，**只是参考，不是标签**）。

要填四个字段：

| 字段 | 填什么 |
|---|---|
| `label` | `correct` / `partial` / `wrong` 三选一（见下面定义） |
| `truth` | 一句话：真实应有的答案，或引擎错在哪里的根因。写业务事实，不写「机器建议说……」 |
| `truth_expect` | 只有 `wrong` 必填：真实应有的裁决，格式三选一：`query`（应当查到数据）、`action(动作名)`（应当执行并落库）、`rejected(规则名)`（应当被这条规则拦下）。`correct` / `partial` 填 `null` |
| `reviewer` | 自己的 id 和角色，如 `{id: xxx, role: 医师}`；文件头的 `reviewer` 与 `labeled_at` 也填 |

三个标签的定义：

- **correct**：引擎的裁决就是业务上应有的裁决。查询查到了对的数据；该执行的执行了且落库对；该拦的被对的规则拦了。
- **wrong**：裁决方向错。该拦没拦、不该拦被拦、拦错了规则、该查到的查成 0 行、动作执行了但落库内容错。
- **partial**：方向对、细节有瑕疵，但不改变裁决。典型：口语里的无关信息（「她女儿说可以买」）漏进了患者可见文案或记录字段；置信度明显偏低但结论对。partial 不落案例，只计成本，所以**拿不准是 wrong 还是 partial 时，倾向 wrong 并在 truth 里写清**。

可选字段 `note`：对后续归因有用的观察（例如「同句在另一个患者上行为不同」），尽量写。

`wrong` 的条目请再填一个 `layer`：`rule`（引擎规则 / 动作实现错了）、`router`（大模型把口语路由错了：选错动作、参数填错、该拦自己先拦）、`seed`（演示租户数据缺字段或缺边）。前五轮的归因报告都按它分组，这次没有专家草案替你们预填。拿不准写 `router` 并在 `note` 说明。

## 这批标注的特别注意

1. **查到 0 行的查询（W47 6 条、W48 12 条）**：先判断「业务上这条数据应该存在吗」。演示租户里对象缺某些状态字段（回执了没 / 签了没 / 推送了没 / 分层哪天出的 / 谁确认的）是已知情况。数据本应存在而引擎查不到 → `wrong`，`truth_expect: query`，truth 里写明是哪个对象缺什么；口语问的东西业务上本来就没有 → `correct`。
2. **W48 指标口径层 11 条全被 R48 拒**（去重仲裁类）。请逐条按业务判断：这些去重请求业务上该放行走弱去重回退，还是该拒。这 11 条对我们的实验特别重要——它们是留出集里第一批去重类案例，直接决定去年两个相互竞争的修法哪个对。请**不要**因为「11 条都一样」就批量复制，每条看一眼参数。
3. **W47 0041**（推送中级告警被 R56 冻结）、**0069**（回执不闭环被 R44 拒）、**0110**（6 天数据出分层被 R01 拒）：机器比对标了 wrong，但按本体定义 R44 / R01 的拦截可能是对的、口语小组的参考期望可能写错了。以业务真值为准，不以 `cq_expect` 为准。
4. **W49 / W49b 的 4 条**都是「把患者数据写到飞书」被 C7 拒。请按合规口径判：患者没有勾选向第三方协作工具传输的同意项，拒是不是对的。
5. **rejected 类的 truth_expect** 要写到具体规则名，不要只写 `rejected`。如果应当被拦但引擎拦的规则不对，`label: wrong`，`truth_expect: rejected(正确的规则)`。
6. 口语里的患者编号、产品编号都是演示租户数据，不涉及真实患者。

## 不要做的事

- 不要改 `utterance` / `engine_actual` / `cq_expect` / `suggested`，不要删条目、不要调顺序。
- 不要看或改 `trajectories/*/audit.jsonl`、`routing.log.*`、`cases/` 下任何文件。
- 不要把 `suggested` 直接抄进 `label`。机器比对只能看「类别一致不一致」，看不出落库内容对不对、拦的规则对不对。
- 不要跳过任何一条。有一条 `label` 为空，整个窗口都不能落案例。
