# Plugin Brief: glycowise（控糖场景）

> Created: 2026-09-04
> 依据：`research/控糖场景深度探索报告-2026-09-04.md` 及 `research/sources/00–05`

## Business Context

**我方**：数联天下，「康养智慧顾问」产品（多智能体 + 企业微信/小程序 + SaaS/私有化）。
**合作方**：至心医养（柳州院中站，62 人，五师共管，糖尿病逆转是明星业务，90% 自费）、德心医养柳州店（英纽林 MNT 固体饮料）。

**要解决的问题**：**整条链都没有系统承载，不只是居家段**（2026-09-05 用户纠正，台账 C-15）。门店侧分诊、问诊建档、体测、方案、企微群跟进五段业务动作在做，但靠纸质方案本 + 飞书多维表格 + 企微群拼凑，体测设备当场打印纸质报告、数据不进系统。居家段更彻底：患者在企微群里口头汇报 7 点指血，健管师手抄进飞书表格，人工判读后给饮食建议。患者一外出就不测、漏测，数据既不连续也不可信，健管师被手工录入吃掉大量时间，复购只能靠卖产品拉动。

**目标**：把**门店侧五段 + 居家段 CGM** 做成一条系统化的链，驱动智能体做指标解读、餐后响应分析和方案草稿，让五师共管从"凭经验+手抄"升级为"数据驱动+人机结合"，并沉淀成门店可售的控糖服务包。

**顺序上门店侧在前**：没有患者档案与体测基线，CGM 数据接进来无处可挂。

**集成前提**：HIS **可对接**（患者基本信息、诊断、用药可取，字段范围待定，D-24）。体测设备能否取数**未确认**，暂按手录或 OCR 纸质报告做保守设计（D-23）。

## 三条不可逾越的约束

1. **CGM 是第三类医疗器械**。门店和平台都不能无证销售。交易走持证厂商/经销商，门店纯引流不碰货不收款。
2. **英纽林是固体饮料**，不得宣称降血糖/修复胰腺/逆转糖尿病，不得称"MNT 医学营养治疗"。现有"血糖分级 → 产品组合表"本身就是违法话术。服务与产品必须在合同、收款、话术、AI 输出上物理分离。
3. **AI 不能自动生成处方**（卫健委互联网诊疗监管细则第 21 条）。智能体只能做数据解读、指南级生活方式建议、监测提醒、异常转介；分型分级结论、用药、疗程方案必须医师/注册营养师签发后才能推送。

## 关键设计事实（供各设计环节引用）

- **数据通道（2026-09-04 更新，已推翻调研结论）**：**硅基动感 CGM 接入已商务确认**，形态是厂商提供 **SDK / 蓝牙协议**，数据粒度是**原始读数（5–15 分钟点）**。
  - 由此成立：指标层自建（TIR/TBR/CV/GMI/AGP 全部自算）、餐后响应配对、德心分级映射、32 条规则完整落地、数据充分性门槛 R01 可真正达标、GMI 可用于缓解判定、**低血糖实时告警链路成立**。
  - 由此引入的新关键约束：SDK/蓝牙是**设备侧直连**，需要 **7×24 常驻采集载体**。当前产品形态是企业微信 + 小程序，**小程序无后台常驻能力**，前台才能连蓝牙——人睡着了就不采集，夜间低血糖无从发现。**载体选型是当前第一技术决策**。
  - **载体已定型（2026-09-04 晚，据硅基答复）**：硅基给的是**移动端 SDK**，且**同一传感器允许多个 BLE 连接并存**。
    - 成品蓝牙网关（Cassia 类）出局——需嵌入式集成或裸协议，移动端 SDK 用不上。
    - **Android App 成为必做项**（原企微+小程序规划外的新增开发承诺，需单独排期预算）。它有两种部署形态，共用一个代码库：① **常插电专用采集盒**（我方资产，发给老年患者，覆盖居家与夜间；无保活问题）② **患者自有手机**（覆盖外出移动段）。
    - 多连接并存 → 盒子与手机可同时连同一传感器，**解掉"外出即断档"这一最大数据缺口成因**，且互为冗余。
    - iOS 后台 BLE 受限，用 iPhone 的中年患者是否也发盒子待定。
    - 华为手表退为 Level 2 震动唤醒增强，不作采集端。
  - 截图 OCR、指血仪标准蓝牙（GATT 0x1808）、人工录入**保留为兜底**，用于载体故障与厂商中断，不再是 Phase 0 主线。
  - 三诺仍建议作为第二供应商谈判，避免单一厂商依赖。
- **临床门槛**：14 天佩戴 + ≥70% 有效数据才出结论。规则优先级：低血糖 → 高血糖 → 波动。老年人切换到老年三分层目标。
- **服务形态**：三档服务包（14 天体验 299–399 元 / 90 天标准 2,980–3,980 元 / 180 天缓解 9,800–12,800 元含结果承诺），CGM 成本占比 30% / 12% / 6%。
- **人机分工**：AI 做日报、异常筛选、方案草稿；人做决策、用药调整、关系维护。目标健管师人均管理 ≥60 人。

## Success Criteria

- 居家血糖数据自动入平台比例 ≥90%（替代手工录入）
- 低血糖事件从产生到健管师响应的时延可测量、可追溯
- 健管师人均管理患者数**分阶段 32 / 40 / 48**（原 ≥60 已被工时重算推翻，见下）
- **医师签发工时不超过其可支配时间**（180 人规模下签发需 3.5h/天，医师比健管师更早触顶）
- 所有对患者输出的内容通过合规闸门，无产品功效声称、无用药建议
- 服务包结营能产出可举证的聚合数据（TIR 改善、体重、减药），不做个案疗效宣传
- **"没有数据"与"没有异常"在老人端、子女端、健管师队列三处都不能长得一样**（最高优先级的显示规则）

## 本轮设计最重要的一条发现

**夜间 Level 2 告警链路的"静默失效"**：没有 7×24 载体时，传感器整夜缓存、次日一次性回填——报告上的夜间 TBR、AGP、`hypo_episode` **全部准确**，而那一夜的低血糖当时没有任何人知道。**指标层完美、安全层为零，且从数据上看不出区别**。连带后果：值班表照排、健管师照守夜、一整夜不会响一次，夜班岗位在制度上存在、功能上为零。

这把 D-01（载体）与 D-02（夜间值班）绑成同一个问题：**只解其一都等于零**。
