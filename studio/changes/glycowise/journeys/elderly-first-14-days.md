## 1. 旅程元数据

| 项 | 内容 |
|---|---|
| **Persona** | 刘阿姨，68 岁，T2D 病程 20 年，HbA1c 7.4%，二甲双胍 + 达格列净 + **伏格列波糖** + 晚间门冬/甘精胰岛素；BMI 21.3，半年体重 56→53 kg；手脚麻、视物模糊；柳州本地，与老伴同住，女儿在深圳 |
| **场景** | 首次购买 A 包「14 天血糖画像」（299–399 元，子女代付礼品版含到店/上门佩戴指导），完成一个完整佩戴周期 |
| **触发** | 二选一：① 女儿过年/探亲回家带她到店；② 门店活动（社区义诊、老客邀约）到店测了一次指血，被邀请入组 |
| **结束态（她的语言）** | **"我知道了这两周我身上发生了什么，知道下一步该干什么，也知道该找谁。"** |
| **运营指标（我们的，不是她的）** | 结营解读到店率 ≥70%；A→B/C 转化率 ≥30%；佩戴完成率 ≥85%。**这三个数是我们的收银台，不是她的成功定义**——分开列，避免把商业指标写成用户价值 |
| **时间跨度** | 第 −7 天（邀约与本人意愿确认）→ 第 17 天（决策落定），约 3.5 周；核心佩戴段 14 天 |
| **评价标准** | **老年三分层目标**（`sources/02` §2.3）：TIR(3.9–10.0) >50%、TBR(<3.9) <1%、TAR(>13.9) <10%、CV ≤36%（**中国口径额外：CV >33% 即软提醒**）。**禁止用成人 TIR>70% 评价她**。TBR(<3.0) 老年表未给百分比，规则上按"**任何 Level 2 事件即触发去强化审查**"处理。她按三分层属**"中等"层**（病程 20 年、已有并发症体感、用胰岛素）：空腹/餐前 5.0–8.3、**睡前 5.6–10.0**（不是门店现行的 5.0）。指南要求"使用低血糖高风险药物者须设血糖**下限**"。临床方向是"稳、不低"，不是"降" |
| **数据门槛** | ATTD 口径是「14 天中 ≥70% 有效数据」（≈10 天）。**A 包只有 1 枚传感器、寿命 14 天，扣除预热与首日偏差，实际可分析窗口约 12–13 天**，故本旅程的结论口径写作 **"≥10 天且 ≥70% 有效数据"**；不足只出趋势描述（R01）。**安全告警不受此门槛限制**，任何时刻都发 |
| **⚠ 设备类型硬约束** | **本旅程只在 rtCGM（实时连续监测）上成立。** isCGM（扫描式）**不产生实时告警**——若采购 isCGM，S2 的全部夜间告警设计、信号 S2/S5/S6，以及"发现你感觉不到的夜间低血糖"这一核心价值主张**全部作废**，须另画一份旅程。设备选型必须在旅程落地前锁定 |
| **⚠ 数据通道（2026-09-04 前提变更）** | **硅基 CGM 接入已商务确认**，形态为厂商 SDK / 蓝牙协议，数据粒度是**原始读数（5–15 分钟点）**。后果：① **患者不再需要手动上传截图/AGP**——原 Phase 0 的"截图上传 + OCR 解析"退为**异常兜底**（网关长期离线、设备换品牌），不再是主路径；② **实时告警链路成立**——S2 的"首次夜间告警"与"伪差假报警"从假设变成**必然会发生的事件**，必须写实并配处置 |
| **⚠ 采集载体：本旅程新增的最大老年痛点** | SDK/蓝牙是**设备侧直连**，需要一个 **7×24 常驻的采集载体**。**小程序无后台常驻，前台才能连蓝牙——人睡着了就不采集**，而夜间恰恰是本产品全部临床价值所在。四个可选载体见 §2.5，**刘阿姨的默认方案是家庭蓝牙网关**（插电即用、零操作）。载体的交付与安装是 S0 的正式步骤，其失败模式是 S1 的主要内容 |
| **触点白名单** | 门店线下、企业微信单聊、企业微信群、电话、小程序（子女侧为主）、**家庭蓝牙网关（无界面设备，不是触点，是基础设施）**、CGM 厂商自有 App（仅在"用患者手机采集"方案下使用，由健管师配置；老人不操作）。**本产品没有原生 App**，老人端不安装任何我方应用 |

## 2. 阶段划分（7 段）

```
[她自己愿不愿意] → [到店建档与佩戴] → [头两天适应] → [皮肤与夜间告警窗口]
   第 −7~−1 天          第 0 天           第 1–2 天         第 3–5 天
        → [看不懂 · 断档 · 打卡疲劳] → [到期与中期兑现] → [结营解读与决策]
                第 6–10 天                第 11–13 天         第 14–17 天
```

命名用她的语言：**"要不要弄这个" → "贴上了" → "有点不习惯" → "痒了、半夜叫了" → "看不懂、出门了" → "快到期了" → "这两周到底怎么回事"**

### 2.5 采集载体四选一（决定夜间有没有数据，进而决定夜间低血糖能不能被发现）

| 载体 | 老人侧操作量 | 7×24 常驻 | 对刘阿姨可行性 | 成本 |
|---|---|---|---|---|
| **家庭蓝牙网关**（插电即用） | **零** | ✅ | ✅ **默认方案** | 硬件 80–150 元/台，A 包按押金回收制摊销 ≈ 25 元/单 |
| 原生 App（我方） | 装 + 授权 + 保活 | ✅ | ❌ 不存在（本产品无原生 App），且她"下载→注册→授权→配对"转化率接近零 | — |
| **硅基自家 App**（患者手机） | 装 + 蓝牙常开 + 后台保活 + 会充电 | ⚠ 国产 ROM"一键清理"是已知高故障点 | ⚠ 仅作**备选**，需现场实测保活存活率 | 0 |
| 华为手表桥接 | 戴 + 充电 | ⚠ 依赖她每天充电 | ❌ 她没有，也不会买 | 用户自备 |

**载体选型规则（写进 S0 的 SOP）**：
1. 默认发**家庭蓝牙网关**；
2. 若居住环境不适合（无固定插座位、卧室离客厅远、经常在子女家住），退到**硅基自家 App + 现场保活实测**；
3. 两条都不成立 → **不得售卖含夜间告警的服务包**，改售不含夜间告警的回顾版，并**书面告知家属"本服务不含夜间兜底"**。

> **不要把载体当成"技术选型"**。对刘阿姨而言，这就是"床头多一个插着电的小盒子"——它是否被拔掉、够不够得着、家里有没有 WiFi，直接等价于"她夜里低血糖能不能被发现"。

## 3. 逐阶段明细

### 阶段 S-1 · 要不要弄这个（第 −7 ~ −1 天）

> **这一段原本不存在**（草稿从"第 0 天到店"开始），是 UX 评审补入的。旅程的触发是"女儿带她来"——**她本人是被决定的那个人**，而被替她做决定的人，会用"悄悄摘掉"来行使否决权。

| 维度 | 内容 |
|---|---|
| **Actions** | 女儿在电话里说"妈我给你订了个东西"；她说"别花那个钱"；到店后被安排签一堆字；**从头到尾没有人单独问过她本人愿不愿意** |
| **Touchpoints** | 电话（女儿）、门店线下 |
| **Thoughts** | "闺女花了钱，我不好说不要""贴身上十四天，出门人家问起来怎么说""签的这是啥，字太小" |
| **Emotion** | 😐 顺从中的保留 |
| **Pain points** | ① 一个看不清字、可能有轻度认知下降的老人当场签署 PIPL 单独同意（授权子女查看夜间低血糖与漏测），**这份同意的有效性存疑**——既是合规风险也是留存风险；② 她对"胳膊上贴东西"的社交顾虑无人问过；③ 没有退出通道，只有"戴上"和"悄悄摘掉"两个选项 |
| **必须的产品动作** | ① **单独问她本人一次**（女儿不在场），口头知情同意录音留痕；② **授权粒度当场二选一**（"闺女能看到你今天好不好" vs "闺女能看到所有细节，包括夜里低血糖和漏测"），选项用她的话说，不用法律术语；③ **前 3 天无理由取消通道**，按已用传感器折算退款——给她一个能说出口的退出方式，好过一个说不出口的摘除 |

### 阶段 S0 · 到店建档与佩戴（第 0 天，门店 75–105 分钟）

| 维度 | 内容 |
|---|---|
| **Actions** | **（前置：设备已由持证厂商/经销商直发到患者或到店代收，患者到店时自带设备——门店不碰货不收款）** → 到店 → 前台分诊 → 医生问诊建档（HIS）→ 健管师带检（一体机 + 体成分 + HbA1c）→ **营养风险两问筛查 + 称重 + 小腿围/握力** → 签同意（见 S-1）→ **登记 1–2 名本地可到场施救者 + 门牌地址**（老伴为默认第一人）→ **载体交付与配置**（见下）→ **健管师现场指导，患者/家属自行完成贴敷**；健管师核对部位、确认信号、留影像记录 → 皮肤保护教学 → **同住老伴同步教学 15 分钟（同场，零边际成本）** → 交付低血糖应急包 → 加企微单聊 + 拉专项群 |
| **Touchpoints** | 门店线下（主）、纸质方案本、企微单聊与群（建立）、**家庭蓝牙网关（交付实物）**、小程序（女儿侧付款与开通子女端） |
| **⚠ 合规必改（运营评审）** | 草稿写"健管师当面佩戴 CGM"，同时**踩了两条不可逾越的约束**：门店不得碰货（三类医疗器械），也不得执行医疗器械操作。<br>→ 门店角色是「**佩戴指导服务**」：现场指导、患者/家属自行贴敷、健管师核对与留痕。**不得表述为"为您植入/安装"**。<br>→ 设备流：厂商/经销商 → 患者（直发或到店代收），**门店不经手货款** |
| **Thoughts** | "这东西贴身上疼不疼？""闺女花了多少钱""洗澡怎么办""医生就说了三分钟""这些字我看不清" |
| **Emotion** | 🙂 期待中带紧张 |
| **Pain points** | ① 教育耗时被低估（>65 岁 CGM 教育平均 41 分钟/人，门店按 15 分钟排班）；② 佩戴当场只教"怎么贴"，没教"痒了怎么办、洗澡怎么办、侧卧怎么睡"；③ 女儿当天就走，交接口头进行、无留痕；④ 营养基线（体重轨迹/蛋白/握力）当前门店完全不采 |
| **必交付的实物（不是话术，是东西）** | ① **葡萄糖片**（她在用 α-糖苷酶抑制剂，只有纯葡萄糖有效）当面放进药盒旁；② **足量试纸 + 采血针**——15–15 法则的复测**必须用指血**（CGM 有 10–15 分钟生理滞后，低血糖时用 CGM 判断回升是错的），而她"试纸舍不得用，一周扎两三次"，家里未必有可用耗材；当面演示一次夜间取用，**放床头固定位置，不是抽屉**；③ **大字应急贴纸**（120 + 健管师号码），贴手机背面与冰箱门；④ 老伴的一张大字应急卡；⑤ **隔离敷料/皮肤保护膜 + 备用敷贴 + 防水贴** |
| **佩戴部位三条禁忌（临床评审补入）** | ① **避开胰岛素注射区**（脂肪增生会同时影响药物吸收与传感器读数）——她每晚注射，部位冲突是必然而非偶发，推荐**上臂后外侧**；② **避开惯用侧卧位那一侧**（压迫伪差是夜间假性低血糖的首因）；③ **MRI/CT/透热治疗前须取下** |
| **胰高血糖素（临床评审补入）** | 她是胰岛素使用者。入组时由**医师评估是否处方胰高血糖素**（注射/鼻用），并对本地可到场施救者做使用培训；若不可及，则必须明确写入"Level 3 唯一处置是 120"，**不得留空**——目前本地施救者被登记了，却没有任何人被赋予可执行的救治手段 |
| **载体交付与家中安装（前提变更后新增的正式步骤）** | 门店侧：现场发网关 → 贴一张**大字标签**（"这个盒子别拔，24 小时插着"）→ 现场用门店 WiFi 试联通 → 打印一张**家中安装图卡**（插座位置示意 + WiFi 密码填写栏 + 网关指示灯颜色对照）。<br>家中侧：**当天或次日必须完成一次远程联通确认**（健管师看到后台有数据 = 安装成功；无数据 = 立刻电话）。<br>**这一步不完成，整个服务就是一个昂贵的空壳**——设备在采数据，但没有任何数据到得了我们这里 |
| **传感器意外脱落的恢复路径（运营评审补入）** | A 包只有 1 枚。**前 7 天内非人为脱落免费补发一枚 + 免费重贴**，作为 S0 皮肤教学的配套承诺，并计入 A 包成本结构。不给恢复路径，等于把一次可挽回的意外直接判成流失，而补发成本远低于一次流失 |
| **本阶段的拦截价值** | **P1 皮肤路径的唯一低成本拦截点就在今天**：先贴隔离敷料再贴传感器、演示部位轮换、演示防水贴洗澡（**明令禁止保鲜膜包裹**——会造成胶布松脱与皮肤浸渍）。这套动作总成本低于一枚传感器，却保住了后面全部临床结论的前置门槛 |

| **Pain points** | ① 传感器**预热期**（多数国产 CGM 1–2 小时，部分品牌首日偏差大）内读数不稳，此时给判断会立刻透支信任；② 她不知道"数据在传"这件事正在发生，缺乏正反馈；③ 洗澡这一问**高频且高危**，处理不好直接掉进 P1 |

| **产品硬规则** | **前 3 天不给任何达标/未达标判断**，只做适应期描述（也是临床上正确的：14 天 + 70% 才是结论门槛）。每日卡片正向:负向内容比 ≥1:1 |

**⚠ 载体的五种真实失败模式（前提变更后新增，本阶段的主要内容）**

> 这五件事**每一件都不是技术故障，是生活**。它们直接决定夜间有没有数据，进而决定夜间低血糖能不能被发现。**载体离线 = 服务归零，但账照付、卡片照发**——如果卡片在网关离线时还写"今天平稳"，那就是本项目最严重的一类虚假安全感。

| # | 失败模式 | 她那边发生了什么 | 可观测特征 | 处置 |
|---|---|---|---|---|
| F1 | **网关没插电 / 被拔了充手机** | 她床头就一个插座，晚上要充手机 | 网关心跳中断，**且**中断时点集中在夜间 | S0 就发一个**插线板**（成本 15 元，比任何软件方案便宜）；F1 触发即电话，不发消息 |
| F2 | **放在卧室外，蓝牙够不着** | 网关插在客厅，她睡卧室，隔一堵墙 | 网关在线但**收不到传感器数据**（心跳有、读数无）——这是与 F1 完全不同的信号 | 电话指导挪位；S0 的家中安装图卡要写"放在床头 2 米内" |
| F3 | **家里没 WiFi / 不知道密码** | 宽带是子女装的，密码在子女手机里 | 网关从未上线过 | **S0 现场就要问清**：家里有没有 WiFi、谁知道密码；无 WiFi 则选 4G 版网关（成本 +30 元/台，含流量卡） |
| F4 | **她自己把网关"收起来了"** | "客人来了不好看""这东西闪灯睡不着" | 心跳中断且不在夜间时点 | 选无闪灯/弱光款；S0 说清"这个不用管它" |
| F5 | **回老家 / 住子女家，网关没带** | 外出场景的必然结果 | 网关离线 + 她人不在家（S3 的外出模式） | 外出模式下**明确告知家属"这几天没有夜间兜底"**，不得静默降级 |

| **Pain points（最密集）** | ① 皮肤问题 45%、疼痛 43%，4–18% 因皮疹停用，**但 81.9% 报告不适的人愿意继续——只要有人处理**；② 夜间侧卧压迫伪差造成假性低血糖告警，**误报一次的代价是之后所有真报警的失效**；③ 她的默认应对是"自己扛 + 报喜不报忧"，系统看不见；④ 她不理会推送后，**数据还在传，健管师看不出任何异常**——这是最危险的盲区 |

> **⚠ 前提变更后，本阶段两个痛点从"假设"升级为"必然"。** 原稿写这一段时，实时告警链路能否成立尚未确定，因此"首次夜间告警"与"伪差假报警"是推测。**硅基接入商务确认后，这两件事一定会发生**——第一次夜间告警大概率就在第 3–5 天，而侧卧压迫伪差是 rtCGM 的固有物理特性，不是软件缺陷。<br>→ 因此本阶段的全部设计（去抖规则、分级策略、归因方法、误报后的关怀触点）**从"备选方案"升级为"上线必备"**，且必须在第一个患者入组前完成，不能排到二期。

**⚠ 皮肤反应是两类，不是一类（临床评审必改）**

| 类型 | 机制 | 典型时点 | 处置 |
|---|---|---|---|
| 刺激性皮炎 / 胶布机械刺激 | 物理与摩擦 | **首枚传感器第 3–5 天** | 隔离敷料、部位轮换、减少牵拉 |
| **变应性接触性皮炎（ACD）** | 敷贴中丙烯酸酯/IBOA 致敏 | **需致敏过程，典型出现在第 2–3 枚（数周后）** | 换敷贴材质、皮肤科转介；**无法事前预筛** |

→ 后果：把皮肤窗口单点化在第 3–5 天，会让 **P1 权重在 A 包内被高估、在 B/C 包续用期被严重低估**，而 B/C 包才是收入所在。B/C 包的第 2–3 枚更换点必须单设一次皮肤复查。

**⚠ 告警逻辑：15 分钟是统计定义，不是实时触发条件（临床评审必改，本文档最重要的一条修正）**

| 用途 | 正确规则 | 依据 |
|---|---|---|
| **回顾性事件计数**（AGP、TBR、绩效） | <3.9（或 <3.0）**持续 ≥15 min** 计一次事件；结束 = 连续 15 min ≥3.9 | Danne 2017 / Battelino 2023，`sources/02` §5.2 |
| **实时告警触发** | **2 个连续读数（≈10 min）** 低于阈值即触发；并叠加**预测性告警**（G<5.0 且 slope ≤ −1，或 G + slope×20 min < 3.9） | R03、R05 |
| **去抖的适用范围** | 只用于**事件统计**与 **Level 1 的降噪**。**绝不用于 Level 2 的实时触发** | 同上 |

> **为什么这条最重要**：CGM 本身有 5–15 分钟生理滞后。"等满 15 分钟再报"意味着真实血浆葡萄糖可能早已进入 Level 3 窗口。**把统计学定义当成实时安全逻辑，是本项目最容易犯、后果最严重的一类错误。**

**⚠ 告警分级必须按"用药 × 无感知低血糖风险"分支，不能一刀切静音（临床评审必改）**

草稿写"老人端只保留 Level 2，Level 1 与预测性告警一律静音"——**对本 persona 恰好是反的**。她用晚间门冬/甘精胰岛素、病程 20 年、老年，正是**无感知低血糖（IAH）高危人群**；指南对这类人的处置是**把低值告警阈值上调到 4.4 并保留告警**，不是关掉 3.9。当前设计对最需要提前量的人取消了提前量。

| 人群 | Level 1（3.0–3.9） | 预测性告警 | Level 2（<3.0） |
|---|---|---|---|
| 未用胰岛素/磺脲、无 IAH 线索 | 老人端静音，并入次日日报 | 静音 | 不可静音、不可关闭 |
| **用胰岛素/磺脲，或有 IAH 线索（本 persona）** | **保留低音提示，阈值上调至 4.4** | **保留** | 不可静音、不可关闭 |

> **Level 2 的"不可静音 + 本机高音响铃 + 语音播报"在无原生 App 的约束下，我方软件做不到**（企微消息不能强制响铃、不能穿透勿扰、不能禁止用户关闭）。因此必须改为**物理与厂商侧方案**：① 把"**Level 2 告警不可被用户关闭**"列为 CGM 厂商选型的**采购硬指标**，由厂商 App 的原生高危告警承担；② 我方并发**电话呼叫**（电话能否穿透夜间勿扰需实测）；③ "120 大按钮"改为 S0 当场配置的**桌面一键拨号快捷方式 + 大字贴纸**，成本近乎为零。

**⚠ "关闭通知"这个信号，技术上拿不到（UX 评审必改）**

在无原生 App 的前提下，**系统观测不到用户关闭微信/企微通知**——那是操作系统级设置，微信生态不开放。原设计的 `silence-detector` 建立在一个拿不到的事件上，**它本身就是一个静默失败**。
→ 重定义为**行为代理信号**：告警发出后 N 分钟内无任何回执 + 无卡片打开 + 无来电接听，**连续 ≥2 次**即判定"事实上已失联"。
→ 真正的兜底改为**不依赖推送的通道**：Level 2 一律并发电话，电话未接即按 §3-D3 的链路升级。

**⚠ 归因回访不能外包给她的回忆（UX 评审必改）**

草稿要求每次告警后 24 小时内回访"昨晚那次是压着了还是真的低"。这是把归因外包给一位**夜间被吵醒、可能有轻度认知下降、且有报喜不报忧既有模式**的老人的记忆——她大概率会说"压着了"，因为那是让所有人省事的答案。**默认归为伪差，会系统性地把真实夜间低血糖洗掉，而这恰恰是本产品唯一的核心价值。**
→ 归因以**客观特征为主**：信号形态（骤降骤回 vs 缓降缓回）、与体位/睡姿时段的相关性、压迫伪差的波形特征、有无指血确认。回访只作补充。**"归因不明"是一个合法结论，不得默认归为伪差。**

**⚠ 用药分支（安全硬约束）**

她在用**伏格列波糖（α-糖苷酶抑制剂）**：低血糖时馒头、饼干、牛奶、无糖酸奶**全部无效**，只能补**纯葡萄糖 15 g**。系统读取用药清单后自动切换话术卡，健管师**无法改回通用版本**。"吃根黄瓜"是门店现行错误话术，系统级禁用零碳水食物作为低血糖/睡前加餐建议。
**睡前加餐阈值同时要改**：门店现行的 5.0 是"良好"层的值；她属**"中等"层，睡前下限应为 5.6**。修掉"黄瓜"却保留错误阈值，是比黄瓜更隐蔽的第二处偏差。

**⚠ 用药清单本身没有维护机制（临床评审补入）**

整条安全链路（`hypo-treatment-by-med`，本项目最高优先级的安全 skill）唯一依赖一个**当前无人负责维护的字段**。她若停用伏格列波糖、或加用 GLP-1，系统不会知道。
→ 用药清单**只能由医师建档/更新**；清单超过 N 天未复核，或患者报告改药 → 话术卡**自动降级为最保守分支**（"立即联系医师 / 仅用葡萄糖"）并进健管师队列。

**⚠ 复测必须用指血**

15–15 法则的闭环判定（补糖后 15 分钟回升 ≥3.9）**必须以指血为准**——CGM 测组织间液，MARD 8–10% + 5–15 分钟滞后。低血糖话术卡上写明"**先扎手指，不看手机上的数**"。这也是 S0 必须发放足量试纸的原因。

**曲线读法（四条判断）**

1. **最低点在 S2（第 3–5 天），不在结营。** 此时投入的边际收益最高：一条"痒不痒"的探针成本近乎为零，却决定后面 12 天的数据能不能达到 70% 门槛。
2. **S3 是"平的假象"。** 情绪没有剧烈下跌，但互动量归零——**这是最危险的形态，因为它看起来像正常**。只能靠 S7/S8/S9 三个行为信号发现。
3. **S5 的分叉是"我们的分叉"，不是她的。** 未到店对我们是转化归零，对她**不必然是谷底**——那 3 次夜间低血糖的发现已经发生了。把商业损失画成用户情绪，会让我们把钱花错地方。她那一侧的情绪**标注为未知，待验证**。
4. **整条曲线是假设。** 验证方法：门店 5 人 × 2 周影随行 + 每日一句话情绪自评（三张表情图片，回复数字）。

**⚠ 探针的电话量必须计入健管师时间账（UX 评审跨文档修正）**

原设计"探针 24 h 无响应视同'是'，直接电话"。老年人对卡片的响应率大概率 <50%——60 人 × 两次探针 × 50% 不响应 ≈ **每天新增 15–30 通电话**，而 journey 02 的时间账只留了"橙档 3 人/天 × 8 min"。**一项未被计入的设计足以吃光全部缓冲。**
→ 两处取齐：① 探针**分批投放**（每天只对处于第 2/4 天窗口的人推，稳态约 8–9 人/天）；② 无响应先**由老伴代答**，再电话；③ 探针产生的电话量单列进 journey 02 §6.2。

## 10. 关键洞察

1. **最低点在第 3–5 天，不在结营日。** 整个行业习惯把资源压在"转化时刻"，但她在第 14 天做的决定，是在第 3–5 天那两个失眠的夜里就已经形成的。**S2 的边际投入回报率是全旅程最高的**，而所需成本低于一枚传感器。

2. **本次评审暴露的最大系统性错误：把"统计学定义"当成"实时安全逻辑"，把"降噪"当成普适善意。** 去抖 15 分钟、静音 Level 1、外出模式降噪、设备告警降级——每一条单独看都合理，叠加在一个用胰岛素、可能无感知低血糖、独居时段长的老人身上，结果是**把提前量全部削掉，只留一个滞后十几分钟的 Level 2 兜底**。进入 skill 实现前必须先按"用胰岛素/磺脲 × IAH 风险"重画一次告警策略分支，这比新增任何功能都重要。

3. **"她没说"不是没问题，是最大的问题。** 她的所有退出都不宣告：痒了不说、不理会推送不说、摘了不说、不续费只说"我再考虑考虑"。因此每个阶段都必须有**不依赖她开口的观测手段**（S1–S12）。而这里有一个更深的教训：原设计里最重要的那个静默检测器（"她关掉了通知"）**技术上根本拿不到**——**我们差点用一个静默失败去检测静默失败**。

4. **A 包卖的不是数据，是一次"发现"。** 她买的是确定性，我们前 13 天给的全是不确定性。唯一能兑现确定性的时刻是 S5 的 30 分钟面对面，而它 100% 由我们控制。**PDF 不是交付物。** 但要注意：未到店对**我们**是转化归零，对**她**不必然是损失——那 3 次夜间低血糖的发现已经发生了。把商业损失画成用户情绪，会让我们把钱花错地方。

5. **对她而言最有说服力的结论，是一条坏消息的好版本**——而且必须由对的人说出口。"我们发现您夜里有 3 次血糖掉到 3.2 以下，您自己没感觉，黄医生已经在看"是健管师能说的极限；"药开重了、该减胰岛素"只能医师面诊后说。**这也顺带说明：老年组的产品价值主张应该是"防低"，不是"降糖"。**

6. **数据不足是常态，且它不该阻断价值兑现。** ≥10 天 + 70% 是出**结论**的门槛，不是出**发现**的门槛。她大概率会在 S3 断档一到三天。**能不能在数据不足时依然让她觉得这钱花得值，是本产品的分水岭。**

7. **她所有的"不配合"都有一个便宜十倍的上游解法。** 摘设备 ← 第 0 天没教隔离敷料；不理告警 ← 实时逻辑用错了定义；不看日报 ← 日报全是红的；不续费 ← 没让她到店。**没有一条需要更强的 AI，全部需要更早的一次人工出现**——这与"自助 42.7% vs 人工支持 89–92%"完全一致，那 46 个百分点就是本产品的全部空间。

8. **数据通道打通了，瓶颈往下游挪了一格——挪到了"床头那个插着电的小盒子"。** 硅基接入解决的是"数据能不能到平台"，但对刘阿姨而言，真正的问题变成了"数据能不能离开她家"。**小程序无后台常驻、前台才能连蓝牙，人睡着了就不采集**——而夜间恰恰是本产品全部临床价值所在。家庭网关是唯一对她零操作的方案，可它的五种失败模式（没插电、隔一堵墙、没 WiFi、被收起来、回老家没带）**全都不是技术问题，是生活**。<br>**最危险的形态是：网关离线，账照付，卡片照发"今天平稳"。** 因此有一条规则的优先级高于本旅程几乎所有功能——**"没有数据"和"没有异常"在老人端、子女端、健管师队列三个地方都不能长得一样**。

9. **最便宜的那个人一直站在旁边，我们没看见他。** 老伴同住、24 小时在场、看得见她所有的"不说"、是天然的第一施救者，而三份草稿给了他零个触点。S0 多花 15 分钟教他，可能比整套告警系统更管用。
