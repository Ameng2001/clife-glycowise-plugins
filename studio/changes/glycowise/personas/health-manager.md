## 设计启示

1. **工作台的第一屏是队列，不是看板**，且队列必须分**两层**（临床专家评审必改：原草稿照搬 AGP 读图顺序，会把急性代谢危象埋在低血糖之后）：
   - **第 0 层「立即处置（红旗）」**——不排队、直接弹屏并同时呼值班：疑似 Level 3 低血糖（叫不醒/抽搐/意识改变）；**疑似急性代谢危象（持续 >16.7 且伴呕吐/腹痛/嗜睡/深大呼吸；SGLT2i 使用者出现上述症状即使血糖不高也算）**；以及胸痛、肢体无力、呕吐不止。**红旗层的动作只有一个——"立即拨 120 并通知医师"，不允许健管师在此做临床权衡**。她"不知道该不该叫 120"的焦虑正是靠这份清单消解的。
   - **第 1 层常规排序**：低血糖 → 高血糖 → **营养风险（体重下降 / 进食减少 / 连续低值）** → 波动 → 数据不足 → 待随访。每条带"为什么进队列"和"建议动作"。
   - 紧急告警走独立链路，不经 LLM 自由发挥。她要的不是漂亮图表，是"今天先干哪三件"。
2. **话术护栏要给"能说什么"，不只是"不能说什么"**：为每类患者提问预置**可直接发送的合规话术卡**（监测方法、低血糖 15–15 法则处置、复诊提醒、转介模板）。纯禁止会让她回到私聊里凭经验答，护栏必须比违规更省力。
   - **护栏必须覆盖三类高风险话术**，触发即拦截并转专业角色：①用药加减停 → 转医师；②分型、疗效、"逆转/治愈" → 转医师；③**面向 ≥65 岁用户的限量类话术**——"主食减半""晚饭别吃了""过午不食""用×××代替一顿饭""少吃点肉"——一律拦截转注册营养师。第三类目前完全没有护栏，却是这套服务对老人造成实际伤害最可能的路径，且"用产品代替一餐"同时构成固体饮料违规宣称（营养专家评审补入）。
   - **护栏的错误恢复面**（UX 评审补入）：(a) 误拦截必须能一键申诉并当场放行（附记录），否则她会改用私聊规避——护栏的失败模式不是违规，是不可见；(b) 已发送内容需支持撤回 + 更正模板，并自动提醒该患者；(c) 拦截率与申诉率作为上线后第一个月的核心可用性指标：拦截率过高说明规则太粗，申诉率为零说明她已经绕开系统。
3. **纠正既有错误知识，而不是只加新功能**：加餐建议库必须由营养师核定并写明碳水克数（"半个馒头 / 一小盒无糖酸奶 ≈ 15 g 碳水"），系统级禁用零碳水食物作为低血糖/睡前加餐建议。
   - **加餐建议库必须按用药条件分支**（营养 + 临床专家一致意见）：系统读取用药清单，对 **α-糖苷酶抑制剂（阿卡波糖/伏格列波糖）使用者，低血糖话术卡自动切换为"只能用葡萄糖片/葡萄糖水，馒头饼干牛奶均无效"**，健管师无法手动改回通用版本。对胰岛素使用者，睡前加餐阈值与内容由医师/营养师在方案中预设，健管师只做转达。上线时配一次专项内训——这是安全缺陷修复，不是可选培训。
4. **AI 出草稿，她做决定，留痕到人**：日报、周报、方案初稿由 AI 生成，她审核编辑后发送；每条对患者输出都记录"AI 生成 / 谁审核 / 何时发出"。涉及方案变更的必须走审核智能体 → 医师签发，她无权直接发。这既是合规要求，也是她"AI 给错我背锅"焦虑的解药。
5. **把"患者不报"从她的失败变成系统的信号**：数据完整率自动计算并进队列（"张伯连续 3 天无数据，可能外出"），提供一键外出模式与一键关怀模板；考核口径应区分"她没跟进"和"患者外出"，否则她会为了指标去伪造/补录数据。
6. **绩效与排班配套改造，且 KPI 必须带安全一票否决**：绩效改按 KPI 计提是产品设计的前提条件而非附属条款——否则工作台里的"合规闸门"会与她的收入直接冲突。同时必须有夜间值班与紧急告警人工兜底安排，不能默认"告警发到群里就有人看"。
   - **TIR 是可以用低血糖"刷"出来的**（临床专家评审必改）：把老人压到 3.9 附近，TIR 上去了，TBR 也上去了；更隐蔽的路径是在高血糖时段摘下传感器，TIR 立刻改善。因此：**TIR 改善只有在 TBR(<3.9) 未恶化、且 ≥65 岁人群 TBR <1% 的前提下才计入绩效**；出现 Level 2 低血糖事件或 TBR 超标的个案，该个案当期不计 TIR 奖金。**有效数据率与佩戴天数是计分的前置门槛**（<14 天或 <70% 一律不计）。老年患者的绩效指标应以"TBR 达标 + 低血糖事件闭环率 + 告警响应时延"为主，TIR 为辅——**对老年人而言，把 TIR 从 55% 推到 70% 的收益，远小于一次夜间 Level 2 低血糖的伤害**。
8. **给她一件资格内就能做的营养工具**（营养专家评审补入）：健管师不能做营养诊断，但可以做**筛查与转介**。工作台内置两问式筛查（"最近三个月体重有没有掉？""最近一周吃饭比平时少吗？"）+ 月度称重录入，任一阳性自动生成「转注册营养师」工单，她只需按一个键。这既补上了当前最大的临床盲区（老人的营养崩塌是缓慢的，不会触发任何血糖告警），又严格落在她的资格边界内——她不做判断，只做发现。
7. **迁移路径要照顾旧习惯**：飞书表格短期内仍是她的心智锚点，过渡期做平台 → 飞书多维表格的单向日汇总同步，但录入入口只保留平台一处，避免双份工作。

## 待确认（用户不在线，Step 5 Validate 未执行）

- **【最值得先验证】手工录入实际耗时与人均管理量。** 整个工作台的 ROI 论证和"人均 60 人"目标都压在这个未实测的数字上，而这恰恰是成本最低、当天就能做的验证。零成本方法（1 天内）：(a) 直接导出飞书跟踪表 6 个月历史记录，按健管师 × 日统计条数与字段填充率——这是**已经存在的、免费的行为日志**，比任何访谈都可靠；(b) 请 2 位健管师连续 3 天做时间日志（每 30 分钟记一次在做什么）；(c) 现场影随行半天，实测"听一条语音抄进表"的单条耗时。三者交叉后才允许写进 ROI 材料。
- 门店是否具备夜间值班能力。若无，低血糖告警的兜底责任人是谁（医师？120？子女？）必须先定，否则告警链路无法设计。
- 现有绩效方案的具体构成（产品提成占比多少），改按 KPI 计提对她收入的影响幅度。
- 健管师的实际学历/培训背景分布，决定话术卡的详细程度与内训时长。
- 店长退出患者企微群这一 SOP 变更的组织阻力（涉及店长的业绩可见性，见 persona 06）。
- 企微群机器人 20 条/分钟限频下，60 人规模的日报推送时序是否需要错峰。
