## 一、流程元数据

| 项 | 内容 |
|---|---|
| **流程名称** | 控糖服务包入组流程 |
| **触发** | 患者到店（自然客流 / 老客转介 / 子女代约 / 线上引流到店）；**必须到店**，不接受纯线上入组 |
| **结束状态** | ① 入组成功（服务包生效 + 数据授权已留痕 + CGM 已佩戴 + **通道连通性已验证** + 平台建档）<br>② 入组成功但暂不佩戴 CGM（仅服务包，指血兜底通道）<br>③ 不入组—转诊（发现急症/危急值/1 型或特殊类型疑似）<br>④ 不入组—患者放弃（价格、意愿、家属不同意）<br>⑤ 挂起（拒绝数据授权 / 授权条件不满足，服务不能开始）<br>⑥ `enrolled_pending_channel`（授权与佩戴已完成，但通道连通性未验证通过，服务包计时未启动） |
| **频率** | 单患者一次性（续约/升级走流程三的续约分支）；门店维度约 5–15 人/周 |
| **边界** | 含：分诊→问诊→体测→入组判定→CGM 交易与佩戴→数据授权→建档。<br>不含：日常监测（流程二）、周期复盘（流程三）、缓解判定（流程四）、英纽林等食品的开单与收款（**独立流程，物理隔离，不在本流程内**） |
| **典型耗时** | 到店 60–90 分钟；HbA1c 院内快检 10 分钟内出，静脉血外送则 T+1 |

**定价隔离（硬约束）**：服务包价格构成中**不得包含任何 CGM 器械成本或摊销**。服务包报价单须列明"本价格仅含健康管理服务，不含 CGM 传感器；传感器由患者自行向持证厂商/经销商购买并支付"。若门店从厂商取得任何按销售额计算的返佣、折扣或结算差价，视同代销，**一律禁止**；合作只能是固定金额的场地/推广服务费，单独签约、单独开票。
（注：brief 中"CGM 成本占服务包 30%/12%/6%"是**成本测算口径**，不得成为定价构成口径——这是两件事，务必在报价单上分开。）

**责任主体划分（贯穿四流程）**：至心/德心医疗机构为**个人信息处理者**及诊疗行为责任主体；数联天下平台为**受托处理者**，仅按机构指令处理，不自行决定处理目的与方式。二者须签署《个人信息委托处理协议》，明确：处理范围与期限、安全措施、再委托限制（转委托须书面同意）、审计权、事件通报时限（≤24h）、终止后数据返还或删除。**若平台自行决定将数据用于产品优化或模型训练，则该场景下转为共同处理者，须另行取得患者同意并在协议中约定连带责任分担。**

## 零、存量患者迁移前置流程（上线硬闸）

现有患者的历史血糖数据分散在企微群聊天记录、飞书表格、纸质档案中，均在无单独同意的状态下产生，是本项目**最大的现实合规敞口**。

```
[平台上线前 / 存量患者首次接入]
    │
    ▼
◇ D0 该患者是否已补签《敏感个人信息单独同意书》（含"历史数据追溯授权"独立勾选项）？
    ├─ 否 → 【硬阻断】
    │         ├─ 历史数据**不得导入平台**
    │         ├─ **不得**用于任何模型训练、聚合统计或案例素材
    │         └─ 源表（飞书/群记录）按原状封存并限制访问，只保留门店必要人员只读权限
    └─ 是 → [历史数据经清洗与单位校验后导入，标 `legacy_import=true` + 补签日期]
```

补签完成率与未补签数据的封存状态列入**每月合规报表**。

- **前置串行闸（不可并行）**：到店 5 分钟内的随机指血筛查（D2）必须先于一切体测与商业动作；数据授权（D9）必须先于 D7 器械环节与佩戴，因为 `sensor_session` 落库已构成个人信息处理。
- **并行 1**：一体机与体成分仪互不依赖，两台设备可同时排队，节省 15–20 分钟。
- **并行 2**：HbA1c 若外送，与"服务包讲解/签约/CGM 佩戴"完全并行，**唯一约束是 D5 缓解路径判定必须等 HbA1c + C 肽 + 抗体齐**。因此：先签 B 包、结果回来再升 C 包，是唯一合规且不卡流程的做法。
- **并行 3**：CGM 交易在持证方渠道进行时，健管师并行完成服务合同签署与企微群建群。
- **合流点**：`平台建档` 是所有并行分支的汇合点——基线快照不全则 patient 档标 `baseline_incomplete`，流程三的 14 天 AGP 解读会带此标记。
- **不可并行**：数据授权（D9）必须在**任何数据处理之前**完成（已前移至 D7 之前）；通道连通性验证（D11b）是所有分支的最终收敛闸。

## 七、关键观察

**瓶颈**
1. **医师判定环节是唯一硬瓶颈**。入组、选包、目标区间设定都压在医师身上，一个门店常只有 1–2 名医师，且他还要出诊。→ 建议把"体测数据汇总 + ABCD 项齐全性检查 + 建议包位"做成工作台预填卡片，医师只做确认/修改（1 分钟内）。
2. **C 肽与抗体检测通常不是门店现场项目**，会把 C 包决策推迟 1–3 天。这是 D5 的天然延迟，必须用"先 B 后升 C"的合同结构吸收。
3. **CGM 交易的合规隔离带来体验断点**：患者要在另一个渠道下单付款，转化会掉。→ 只能靠"持证方小程序嵌入引导 + 门店协助但不收款"来压缩摩擦，不能靠代收。

**自动化候选**
- 基线快照结构化（一体机/体成分仪结果 OCR/直连入档）——高价值，替代纸质方案本。
- 授权留痕全链路（条款快照 hash、版本号、撤回入口）——必须自动化，否则举证不能。
- ABCD 项齐全性检查与缺项提示（R30 的机械部分）。
- sensor_session 建会话与预热窗口标记（R01 前置）。
- 企微建群 + 机器人 key 下发 + 告警接收人配置。

**不可自动化**
- 入组与否、分层、目标区间（D4/D5/D6 的临床结论）——**医师签发**。
- 同意书的解释与确认——需人当面讲清"共享给谁、存多久、怎么撤回"。

**审计留痕清单（合规官要求）**
- `consent_record`：条款快照 + 版本号 + 签名 + 时间戳 + 撤回记录，**留存 ≥3 年**。
- `device_transaction_ref`：只存持证方订单号引用，平台不存支付信息。
- `enrollment_decision`：医师 ID + 判定依据 + 服务包 + 目标区间版本。
- **PIPIA（个人信息保护影响评估）**：处理敏感个人信息前必须完成并留档，报告**留存 ≥3 年**（PIPL 第 55/56 条）。**触发重评的事件**（任一发生即须在 15 个工作日内更新 PIPIA 并重新审批）：新增/更换 CGM 厂商、新增任何受托处理方（外呼、短信、云服务）、通道降级或升级、模型或 prompt 重大版本变更、新增数据用途（如聚合研究）、发生个人信息安全事件。**未完成重评前，新增链路不得上线。**
- **《个人信息委托处理协议》**与《个人信息共享清单》版本快照。
- **生成式 AI 算法备案号**（见流程二/三），未备案模型不得接入患者可见链路。
- 【建议单独出具】《数据留存与销毁矩阵》：原始读数 / AI 中间产物 / 餐食照片 / 审计日志 / 同意记录各自的留存年限与销毁方式——目前四份流程只明确了 `consent_record ≥3 年`，其余年限未定，是已知敞口。

### 载体交付的五种失败模式（**全是生活，不是故障**）

这五种是旅程图在真实患者家里识别出来的，**没有一件是技术故障**。工程上把它们当"设备异常"处理，方向就错了——它们的解法一半在硬件选型、一半在 S0 现场的 SOP，几乎没有一条靠软件重试能解决。

**平台侧能否感知，取决于"心跳"和"读数"是两个独立信号**——这是本节最关键的一条设计要求：只有把二者分开上报，才能区分 F1 与 F2。

| # | 失败模式 | 生活里的原因 | 平台侧信号 | 多久能感知 | 触发的工单 |
|---|---|---|---|---|---|
| **F1** | **没插电 / 被拔了充手机** | 床头就一个插座，晚上要充手机 | **心跳中断**，且中断时点**集中在夜间**（这个时间模式本身就是证据） | 心跳间隔 × 2（建议 ≤10 分钟） | **电话工单，不发消息**（她正是因为在用手机才拔的盒子，消息发过去也没用）。连续 2 晚 → 补发插线板 |
| **F2** | **放在卧室外，蓝牙够不着** | 盒子插在客厅，人睡在卧室，隔一堵墙 | **心跳有、读数无**——与 F1 完全相反的信号组合 | 2 × 采样间隔无读数（10–30 分钟）后判定 | 电话指导挪位置；回访确认；安装图卡补"床头 2 米内" |
| **F3** | **家里没 WiFi / 不知道密码** | 宽带是子女装的，密码在子女手机里 | **从未上线过**（`last_seen` 为 null） | 离店后 2 小时未见心跳即判定 | **应当在门店就拦住**（D11c 硬闸）；漏出去了则直接联系**子女**而非老人；改配 4G 版 |
| **F4** | **被"收起来了"** | "客人来了不好看""闪灯睡不着" | 心跳中断，且**不在夜间时点**（与 F1 靠时间模式区分） | 心跳间隔 × 2 | 电话；选无闪灯/弱光款；S0 话术加一句"这个不用管它，也不用收" |
| **F5** | **回老家 / 住子女家，盒子没带** | 外出场景的必然结果 | 心跳中断 + 人不在家（结合流程二 `away_mode`） | 心跳间隔 × 2，与 D23/D24 的外出确认合流 | **不静默降级**：必须**明确告知患者与家属"这几天没有夜间兜底"**。这是流程二 §2.5b 的强制告知，豁免于触达封锁 |

**三条从这张表推出的设计约束**：

1. **心跳与读数必须是两个独立信号。** 合并成一个"在线"布尔值，F1 与 F2 就再也分不开——而它们的处置完全不同（一个是补插线板，一个是挪位置）。
2. **F1 与 F4 靠"中断时点的分布"区分，不靠患者自述。** 老人对"我是不是拔了盒子"的回忆不可靠。用客观的时间模式判，比打电话问准。
3. **五种失败模式里有四种的最佳解法在门店，不在平台**：插线板、4G 版、无闪灯款、现场必问三题。**为一个 15 元插线板能解决的问题去写重试逻辑，是把生活问题当成软件问题。**
