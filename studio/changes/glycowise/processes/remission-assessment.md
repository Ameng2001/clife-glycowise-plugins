# 流程四：缓解判定与退出（Remission Assessment & Exit）

> glycowise 控糖场景 · process-flow
> Created: 2026-09-04 ｜ 主导：architect ｜ 评审：diabetes-cgm-expert、cgm-data-integration-expert、compliance-officer
> 依据：`sources/02` §7 §8（R01/R28/R29/R30/R32）、`sources/04` 合规、报告 §4.2 C 包结果承诺

---

## 一、流程元数据

| 项 | 内容 |
|---|---|
| **流程名称** | 强化期结束 → 停药观察 → 停药 ≥3 个月 → 复测 → 缓解判定 → 维持随访 / 结果承诺 → 数据归档 |
| **触发** | C 包（180 天缓解包）强化期结束；或 B 包患者在医师评估后进入减药/停药路径 |
| **结束状态** | ① 达到缓解标准 → 进入年度维持随访 ② 未达缓解但达减重 ≥10% → 部分达标，续维持期 ③ 未达缓解且未达减重 → **触发结果承诺（赠 3 个月维持期）** ④ 停药后血糖反弹 → 复药，退出缓解路径 ⑤ 患者中途退出 ⑥ 数据归档与授权处理完成 |
| **频率** | 单患者一次；C 包约在第 90–180 天区间走完全程；缓解者此后每年复查一次 HbA1c |
| **边界** | 含：停药决策的支撑、停药观察期监测、90 天计时、复测、缓解判定、承诺兑现、归档与授权处理。<br>不含：日常告警（流程二）、常规月度复盘（流程三）。<br>**减药与停药的决定权 100% 在医师**，本流程只负责提供证据、计时、监测与留痕 |
| **责任主体** | 至心/德心医疗机构为**个人信息处理者**与诊疗行为责任主体；数联天下平台为**受托处理者**，按机构指令处理，不自行决定处理目的与方式。二者须签《个人信息委托处理协议》（处理范围与期限、安全措施、再委托限制、审计权、事件通报 ≤24h、终止后返还或删除）。平台若自行将数据用于产品优化或模型训练，该场景下转为**共同处理者**，须另行取得患者同意并约定连带责任 |
| **硬约束** | 缓解 = 停用**所有降糖药** ≥3 个月后 HbA1c<6.5%（或 GMI<6.5%，需 R01 通过）。对外**禁用**"逆转/治愈"；"缓解"只能在医师面诊语境、引用共识严格定义时使用，**不得用于广告** |

## 二、完整流程图

### 2.1 主干

```
[Trigger: C 包强化期结束（或 B 包医师评估后进入减药路径）]
    │
    ▼
[汇总强化期证据包：14 天 AGP + TIR/GMI/CV 趋势 + 体重与腰围轨迹
 + 用药清单变化 + HbA1c 序列 + 依从性]
    │
    ▼
◇ D1 数据是否充分？（R01：days≥14 AND active%≥70）
    ├─ 否 → [不得进入缓解判定]
    │         → [补足佩戴 14 天再判；期间维持现有方案]
    │         → 回到本流程起点
    └─ 是 → 继续
    │
    ▼
◇ D2 ABCD 适宜性是否仍成立？（R30）
    （抗体阴性 AND (BMI≥25 或腰围男>90/女>85 起始)
     AND **空腹 C 肽≥1.1 ng/ml 且餐后 2h C 肽≥2.5 ng/ml** AND 病程≤5 年）
    ├─ 否（如后续查出抗体阳性 / C 肽低）
    │      → [退出缓解路径，转常规控糖管理]
    │      → [**主动向患者说明并调整合同预期**（C 包结果承诺条款需覆盖此情形）]
    └─ 是 → 继续
    │
    ▼
◇ D3 医师是否判定可以尝试停药？
    条件参考（医师综合判断，非系统自动判定）：
      · 强化期血糖持续达标（TIR 达标、GMI 趋近或 <6.5%）
      · 无频繁低血糖（TBR 达标，R09 未触发）
      · 减重达到预期（缓解与减重强相关：DiRECT 减重≥10kg 者 81% 缓解）
      · 无急性并发症、无感染/应激状态
    ├─ 否 → [继续强化期或调整方案] → 回流程三
    └─ 是 → [医师签发《减药/停药计划》：逐步减停顺序、时间表、
             监测加密要求、复药红线（明确写明什么情况必须复药）]
             → [**同时配发血酮仪或尿酮试纸并现场教学**，明确自测触发条件：
                G>13.9 且伴口渴/多尿/恶心，或任何时候出现恶心呕吐乏力]
                ※ 没有酮体检测手段，D4 的"酮体阳性"红线永远触发不了；
                  而停药后失代偿的 LADA 患者正是酮症高发人群。
              ※ **原文完整性约束**：《减药/停药计划》以医师签发的**原文快照**
                （PDF/图片 + 文本 hash）承载与推送，系统与智能体**不得摘要、改写、
                翻译、结构化拆解，也不得在提醒文案中生成用药内容**。
                提醒文案只允许固定模板「今天是医师减停计划的第 N 天，
                请按医师原方案执行并完成打卡」，**不得复述具体药名与剂量**。
                任何对该文档的渲染差异均须可比对原文 hash。
              ※ 系统只承载与提醒，**不生成、不建议、不修改**用药内容
    │
    ▼
════════════ 【停药观察期 — 监测加密】 ════════════
    │
    ▼
[启动 `remission_clock`：停用**最后一种**降糖药的日期为 Day 0]
 ※ 计时基准由医师在工作台确认，不由系统从用药记录自动推断
 ※ 只要有任一降糖药在用（含二甲双胍），计时不启动/重置
    │
    ▼
[停药观察期监测强化（前 4 周）]
    ├─ CGM 持续佩戴（C 包预留枚数）
    ├─ 告警阈值收紧：R09 门槛下调，反弹更早发现
    ├─ 每周指标简报直送医师（不只推患者）
    └─ 健管师每周 1 次主动随访
    │
    ▼
◇ D4 停药后是否出现血糖反弹或安全事件？
    判定（建议阈值，需临床确认，建议固化为 R33）：
      · **连续 7 天平均葡萄糖 ≥8.6 mmol/L**
        （对应 GMI 约 7.0%，但**此窗口不得标称为 GMI**——GMI 的定义前提是
         14 天 + ≥70% 数据，7 天窗口算出来的不是 GMI），或
      · 14 天滚动 GMI ≥7.0%（窗口够时以此为准），或
      · TAR>10.0 连续 7 天 ≥50%，或
      · 任一日 G>16.7 持续 ≥1h（R11），或
      · 出现高血糖症状/酮体阳性（R11/R12），或
      · **停药后出现任一 Level 1 及以上低血糖事件**
        → 立即推医师。停药患者本不应发生低血糖，这提示诊断或其他药物问题，
          **须排查而非简单归因**，或
      · **体重非计划性下降 + 血糖快速恶化 + 酮体阳性**
        → 立即推医师，并**复查 GADA/IA-2A 与 C 肽以排除 LADA/1 型**，
          不得简单归因为"反弹"直接复药了事
    ├─ 是 → [立即推医师] → ◇ D5 医师是否决定复药？
    │            ├─ 是 → [复药 → `remission_clock` **清零**]
    │            │         → [退出缓解判定，转维持管理]
    │            │         → 跳至 §2.3 结果承诺判断
    │            └─ 否 → [加强生活方式干预，继续观察，缩短复评间隔]
    └─ 否 → 继续
    │
    ▼
◇ D6 停药是否已满 90 天？（R29）
    ├─ 否 → [继续观察] → [每 30 天生成一次停药期简报] → 回 D4
    └─ 是 → 继续
    │
    ▼
════════════ 【缓解判定复测】 ════════════
    │
    ▼
[安排到店复测（并行）]
    ├─ [静脉血 HbA1c]（**首选判定依据**）
    ├─ [空腹血糖 FPG]
    ├─ [佩戴 CGM 14 天 → GMI]（HbA1c 不可靠时的替代）
    ├─ [体重、腰围、体成分]
    └─ [必要时复查 C 肽、肝肾功能]
    │
    ▼
◇ D7 HbA1c 是否可靠？（R17：|GMI−HbA1c|≥0.5% 或有贫血/血红蛋白变异）
    ├─ 可靠 → 以 HbA1c 判定
    └─ 不可靠 → [**优先用 FPG<7.0 替代**]
                  ※ **仅在下列条件全部满足时才允许用 GMI<6.5% 替代**：
                    ① 复测窗口 14 天的读数 **100% 来自单一厂商的连续监测通道**
                       —— ~~`source_channel=vendor_api`（云到云）~~
                       → **修订（2026-09-04）：`source_channel ∈ {vendor_api,
                         sdk_ble_direct}`**，即**云到云 或 SDK/BLE 直连**均可，
                       无 OCR、无手工录入、无指血补数
                       ※ **二期双路并存不破坏"单一来源"要求**：采集盒与患者手机
                         连的是**同一枚传感器**（同一 `device_serial`、同一
                         `vendor`、同一 `sensor_model`），两路只是**同一数据源的
                         两条传输路径**，不是两个来源。本条要求约束的是
                         **测量来源**，不是**传输路径**。
                       ※ 但由此产生一条实现要求：判定前必须确认两路读数已正确
                         去重（见 processes/README §主线 3 的双路去重口径）。
                         **若 `duplicate_by_carrier` 标记的读数进了分母或分子，
                         active% 会虚高，缓解判定就建立在一个被灌水的门槛上**
                       ※ 混合通道（如 14 天中 3 天走 OCR 兜底）仍然**不满足**本条
                    ② 全窗口 `vendor` 与 `sensor_model` 一致，
                       无跨品牌、无跨代际换机
                    ③ `active% ≥70%`，且窗口内 `warmup / out_of_range / noise /
                       reattached` 占比 ≤5%
                    ④ 该品牌的 MARD 与准确度声明已在 `channel_registry` 登记
                    任一条不满足 → **不得用 GMI 判定缓解**，
                    只能推迟复测，或以静脉血 HbA1c/FPG 为唯一依据
                  ※ 判定时刻必须固化 `remission_evidence_pack`：
                    原始读数导出 + 通道构成占比 + 全部质量标记 + 传感器序列号清单，
                    与判定结论一并签发留痕
    │
    ▼
◇ D8 是否达到缓解标准？（R29）
    条件：停用**所有**降糖药 ≥90 天 **AND** HbA1c<6.5%（或 GMI<6.5% / FPG<7.0 替代）
    │
    ├─ 是 → 【达标】
    │         ▼
    │     [医师面诊告知：使用"缓解"一词，**必须同时说明**
    │      ① 这不是治愈 ② 需每年复查 HbA1c ③ 体重反弹会复发
    │      （DiRECT 5 年缓解率降至 13%）]
    │         ▼
    │     [平台标记 `remission_status=in_remission` + 判定依据快照 + 医师签发]
    │         ▼
    │     [生成《年度维持随访计划》]
    │      · 每年至少 1 次 HbA1c 复查（提醒自动排程）
    │      · 每季度体重/腰围自测上报
    │      · 每年 1 次 CGM 复评（可选，作为增值维持包）
    │      · 反弹红线：体重回升 >5% 或 FPG≥7.0 → 立即复诊
    │         ▼
    │     ◇ D9 是否购买年度维持包？
    │         ├─ 是 → [维持包生效，回流程二（低密度监测模式）]
    │         └─ 否 → [仅保留年度提醒（免费轻服务）] → §2.4 归档
    │
    └─ 否 → 【未达标】→ §2.3
```

### 2.3 未达标与结果承诺

```
【未达缓解标准】
    │
    ▼
◇ D10 是否达到"减重 ≥10%"？（C 包承诺的另一条达标线）
    ├─ 是 → [部分达标：不使用"缓解"字样，客观呈现改善]
    │         → [医师评估是否延长停药观察或恢复小剂量药物]
    │         → [推荐维持包（付费）] → §2.4
    │
    └─ 否 → 【触发结果承诺】
              ▼
        ◇ D11 是否满足承诺兑现条件？
            兑现前提（合同应明确）：
              · 患者依从性达门槛（如佩戴率 ≥70%、到店触点完成 ≥80%、
                方案执行打卡 ≥60%）
              · 未擅自使用其他减重/降糖干预
              · 未因不可归因原因中断（长期住院、其他重大疾病）
            ├─ 满足 → [赠 3 个月维持期：CGM 枚数、随访触点、AI 服务按维持包配置]
            │           → [店长/健管师书面确认承诺兑现，落库留痕]
            │           → [进入 3 个月维持期 → 回流程二 + 流程三（低密度）]
            │           → [维持期结束再评一次] → §2.4
            │
            └─ 不满足 → [出示依从性数据，与患者沟通]
                          → ◇ 争议？
                              ├─ 是 → [店长 + 医师介入，走客诉流程；
                              │        必要时按商务惯例部分兑现]
                              └─ 否 → [说明并结营] → §2.4
```

## 三、判断点表

| ID | 判断 | 条件 | 真路径 | 假路径 | 规则/依据 |
|---|---|---|---|---|---|
| D1 | 数据充分？ | days≥14 AND active%≥70 | 进入判定 | **不得判定**，补足佩戴 | **R01** |
| D2 | ABCD 仍成立？ | 抗体阴性 AND (BMI≥25 或腰围男>90/女>85) AND **空腹 C 肽≥1.1 ng/ml 且餐后 2h C 肽≥2.5 ng/ml** AND 病程≤5 年 | 继续缓解路径 | 退出缓解路径，转常规管理并调整合同预期 | **R30**（中国共识 2021） |
| D3 | 可以尝试停药？ | 医师综合判断（血糖持续达标 + 无频繁低血糖 + 减重达标 + 无急性状况） | 医师签发减停计划 | 继续强化期 | **医师专属，AI 与系统不得建议** |
| D4 | 停药后反弹或安全事件？ | **连续 7 天平均葡萄糖 ≥8.6 mmol/L**（不得标称 GMI）；或 14 天滚动 GMI≥7.0%；或 TAR>10.0 连续 7 天 ≥50%；或 G>16.7 持续≥1h；或症状/酮体阳性；或 **停药后出现任一 Level 1 及以上低血糖事件**；或 **体重非计划性下降 + 血糖快速恶化 + 酮体阳性** | 立即推医师；后两者须排查病因（低血糖排查用药与诊断；酮症排查 LADA/1 型，复查 GADA·IA-2A 与 C 肽） | 继续观察 | **R11/R12**；阈值【待临床确认，建议固化为 R33】 |
| D5 | 医师决定复药？ | 医师判断 | 复药，`remission_clock` **清零**，退出判定 | 加强干预继续观察 | 医师专属 |
| D6 | 停药满 90 天？ | Day 0 起 ≥90 天，且期间**无任何降糖药**（含二甲双胍） | 进入复测 | 每 30 天出简报，继续观察 | **R29**（ADA 2021） |
| D7 | HbA1c 可靠？ | \|GMI−HbA1c\|<0.5% 且无贫血/Hb 变异 | 以 HbA1c 判定 | **优先 FPG<7.0**；用 GMI<6.5% 替代须四条全满足：① 14 天读数 100% 来自单一厂商的连续监测通道（~~仅云到云~~ → **修订：云到云 `vendor_api` 或 SDK/BLE 直连 `sdk_ble_direct` 均可**；二期双路并存因同源同传感器**不破坏**单一来源要求，但须先完成双路去重）② 全窗口同 vendor 同 sensor_model ③ active%≥70 且 warmup/out_of_range/noise/reattached 占比 ≤5% ④ 该品牌 MARD 已在 `channel_registry` 登记。任一不满足 → 不得用 GMI 判定缓解 | **R17 / R29**；缓解是法律与商业后果最重的结论 |
| D8 | 达到缓解标准？ | 停药≥90 天 AND HbA1c<6.5%（或替代指标） | 标记缓解 + 医师面诊告知 + 年度随访 | 走 §2.3 未达标分支 | **R29** |
| D9 | 购买年度维持包？ | 患者决策 | 维持包生效，低密度监测 | 仅保留年度免费提醒 | 商业 |
| D10 | 减重 ≥10%？ | 相对基线体重下降 ≥10% | 部分达标，客观呈现（**不用"缓解"**） | 触发结果承诺 | 报告 §4.2；DiRECT 证据 |
| D11 | 承诺兑现条件满足？ | 佩戴率≥70% AND 触点完成≥80% AND 打卡≥60% AND 无外部干扰因素 | 赠 3 个月维持期，书面留痕 | 出示数据沟通，争议走客诉 | 合同条款【待法务确认】 |
| D12 | 继续授权？ | 患者意愿 | 延续授权并记录期限 | 执行撤回流程 | **PIPL 第 15 条撤回权** |
| D13 | 数据可删除？ | 是否属诊疗相关记录 | 诊疗记录按医疗档案留存；其他删除或匿名化 | — | PIPL vs 病历管理规定 |
| D14 | 纳入聚合数据集？ | 患者是否授权二次使用 | 匿名化纳入，输出带样本量与口径 | 排除 | **R32**；医疗广告办法 §7 |

## 四、并行说明

```
【停药观察期，三路并行】
[CGM 连续监测 → 流程二实时告警]  ──┐
[每周指标简报 → 医师]             ──┼── 并行，合流于 D4 反弹判定
[健管师每周随访 → 主观症状/依从性] ──┘

【复测日，四路并行】
[静脉血 HbA1c] ──┐
[FPG]           ──┤
[体重/腰围/体成分]├── 并行采集，合流于 D7/D8 判定
[CGM 14 天 GMI] ──┘
  ※ CGM 14 天必须**提前 14 天启动**，否则复测日拿不到 GMI —— 这是最容易漏的排程依赖

【归档阶段】
[结营报告生成] ──┐
                  ├── 并行，合流于流程结束
[授权状态处理]  ──┘
```

**严格串行、不可并行的部分**：
- `remission_clock` 90 天计时期间不得有任何降糖药 —— 一旦复药即清零，无法"并行凑天数"。
- 缓解结论必须在**复测结果全部到齐后**由医师一次性判定，不允许"先告诉患者可能缓解了"。

## 七、关键观察

**瓶颈**
1. **90 天计时是刚性的，商业周期不能压缩它**。C 包 180 天 = 强化期 + 停药观察 90 天 + 复测，时间上非常紧。若强化期用满 90 天，停药观察刚好卡在包期结束，几乎没有缓冲。→ 建议 C 包合同期设计为"180 天服务 + 判定窗口延展"，或强化期压到 60–75 天。
2. **复测的 CGM 排程依赖最容易漏**：GMI 要 14 天数据，必须在复测日前 14 天启动。这是纯排程问题，但漏了就得推迟判定，直接影响承诺兑现时点。
3. **依从性判定是结果承诺的争议核心**。如果佩戴率/打卡率只在结营时拿出来，一定会吵。必须做成患者端持续可见的进度条。
4. **医师停药决策的心理成本**。停药有风险，医师天然保守；若绩效与"缓解率"挂钩会诱导冒进，若不挂钩则没人愿意停。这个激励设计是业务风险，不是技术问题。

**自动化候选（安全）**
- `remission_clock` 计时与用药状态一致性校验（有药即阻止计时）。
- 反弹规则监测（D4，确定性阈值）。
- 复测前 14 天的 CGM 启动提醒、年度 HbA1c 复查提醒排程。
- 判定依据快照落库、归档状态机、授权撤回的技术执行。
- 聚合数据集的匿名化与统计口径生成。

**必须由人（红线）**
- 是否可以停药、如何减停、是否复药 —— **只能医师**。
- 缓解判定的最终结论与告知 —— **只能医师面诊**。
- 承诺兑现的商务裁量。

**合规观察**
- "缓解"是一个**有严格定义的临床术语**，不是营销词。系统里应把它建模为带判定依据快照的状态，而不是一个可以随便打的标签。
- Virta 口径的"逆转"（允许保留二甲双胍）与 ADA/中国共识的"缓解"数字不可混用。若门店引用任何外部数字，必须标注定义。
- 结果承诺（赠 3 个月）本质是商业让利，**不是疗效担保**。合同措辞必须避免被解读为"承诺治疗效果"，否则同时踩医疗广告与消费者权益两条线。
