## 这一轮的结论（进论文）

**闸门第一次面对朴素修法，八臂全部放行。** 两份修法在 pass 判据（action 是否 commit / rejected 规则名）下逐行相同，S（扰动一致）与 W_family 也相同，W_evid 未计算；唯一的差别在落库状态——P9b 把 dup1 当新读数入库、P9a 标 superseded——而现有判据读不到落库状态。所以不是三维闸门选错了，是**三维读数的粒度到不了「写对了什么」**：T/A 只看裁决类别，S 只看裁决在变体间是否一致，W_family 看场景覆盖，W_evid（证据率）本可以区分（P9a 的 evidence verdict=duplicate、ref 非空）但 growth_metrics 还没实现它。

含义：amend-v2 §5 的「朴素修复臂」要有区分力，案例判据必须能断言落库状态（如 `expect_state: {GlucoseReading r-P0045-dup1: {quality_flag: superseded}}`）或 W_evid 必须落地；否则朴素修法与根因修法在闸门面前是同一个东西。这比「八臂同判」更强：它说明一维 / 三维之争在当前判据下根本没有被测到。
